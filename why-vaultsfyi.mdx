This page helps you decide whether vaults.fyi fits your product and which part of the API to start with. It covers what vaults.fyi replaces, who it is for, which capabilities are generally available (v2) versus Beta, and a concrete first integration per use case. vaults.fyi is a REST API at `https://api.vaults.fyi` (key in the `x-api-key` header) that returns normalized data for 3,000+ DeFi yield vaults on 80+ protocols and 22 EVM networks, builds unsigned vault transactions, and reports wallet positions. Solana vaults are available on the Beta SVM endpoints.

## What vaults.fyi replaces

| Without vaults.fyi | With vaults.fyi |
| - | - |
| One adapter, transaction builder and data pipeline per protocol | One schema for every vault (`GET /v2/detailed-vaults`) and one transaction pattern (`context` → `{action}`) |
| Protocol-reported or forward-looking APYs that are not comparable | Realized APY computed the same way for every vault from onchain share prices, net of fees, in five windows (`1hour`, `1day`, `7day`, `30day`, `90day`) |
| A hand-maintained allowlist for risk screening | Reputation Score (`score.vaultScore`), `flags`, `warnings`, holder data and benchmarks to screen with |
| No view after the user deposits | Positions, returns, events, idle tokens and reward claims per wallet (`/v2/portfolio/*`) |

## Who uses it

### Wallets, exchanges and consumer apps

- Turn idle wallet balances into deposit suggestions (`GET /v2/portfolio/idle-assets/{userAddress}`, `GET /v2/portfolio/best-deposit-options/{userAddress}`).
- Let users deposit, redeem and claim rewards without custody: the API returns unsigned calls that the user's wallet signs and sends directly to the protocol contract.
- Show positions, returns and history after deposit.
- Measure the TVL your app drives with the attribution suffix ([TVL attribution](/concepts/tvl-attribution)).

Guide: [For wallets and apps](/use-cases/for-wallets-and-apps).

### Analysts and data teams

- Query APY, TVL, fees, rewards and metadata across the market without running an indexer.
- Separate base yield from reward yield: `apy.<window>.base` and `apy.<window>.reward` for the windows `1hour`, `1day`, `7day`, `30day` and `90day` (the per-vault `/apy` endpoint returns `1day` to `90day` only).
- Pull historical APY, TVL and share price (`GET /v2/historical/{network}/{vaultId}`).
- Compare against USD and ETH benchmark rates (`GET /v2/benchmarks/{network}?code=usd`).

Guide: [For analysts](/use-cases/for-analysts).

### Protocols and curators

- Get your vaults in front of the wallets and apps that integrate vaults.fyi (listing: see [FAQ](/resources/faq)).
- See which partners route deposits into your vaults via the attribution portal.
- Show performance against benchmarks.

Guide: [For protocols](/use-cases/for-protocols).

### AI agents

- Discover and compare vaults with structured filters, then fetch transaction context and unsigned payloads for the user to approve.
- Use the hosted MCP server (`Authorization: Bearer <key>`) or REST (`x-api-key`), or pay per request with x402 and no key.

Guides: [AI agents overview](/ai-agents/overview), [Rules for agents](/ai-agents/rules-for-agents), [Transaction safety](/ai-agents/transaction-safety).

## Capabilities and stability

| Capability | What you get | Stability |
| - | - | - |
| Market data | APY, TVL, fees, rewards, capacity, assets, protocols, curators, networks, tags | v2 (GA) |
| Risk context | `score` object (Reputation Score and components), `flags`, `warnings`, `holdersData`, benchmarks | v2 (GA) |
| History | APY, TVL, share price, asset prices, historical benchmarks | v2 (GA) |
| Near-real-time state | Share price, total assets, total supply, asset price read from chain | v2 (GA) |
| Transactions | Unsigned `deposit`, `redeem`, `request-redeem`, `claim-redeem`, `request-deposit`, `claim-deposit`, `start-redeem-cooldown`, `claim-rewards` calls; no vaults.fyi wrapper contract | v2 (GA) |
| Portfolio | Positions, idle assets, total returns, events, best vault, best deposit options | v2 (GA) |
| Borrowing | Borrow markets, positions, `supply`/`withdraw`/`borrow`/`repay` payloads | Beta |
| Solana vaults | SVM vault data, positions and transactions | Beta |
| Advanced analytics | Max drawdown, withdrawal-pause ratio, composition, utilization | Beta |
| Attribution | Calldata suffix plus reporting in portal.vaults.fyi | v2 endpoint + portal |
| Agent access | Hosted MCP server, x402 pay-per-request | — |

Beta endpoints work but may change before general availability. See [Versioning](/api-reference/versioning).

## Start small: the first integration per use case

| Goal | First calls | Credit cost (from [Credits](/plans/credits)) |
| - | - | - |
| Show a vault list | `GET /v2/detailed-vaults` | 1 + 3 per vault returned |
| Show one vault | `GET /v2/detailed-vaults/{network}/{vaultId}` | 3 |
| Build a deposit | `GET /v2/transactions/context/{userAddress}/{network}/{vaultId}`, then `GET /v2/transactions/deposit/{userAddress}/{network}/{vaultId}?assetAddress=<token>&amount=<base units>` | 3 + 5 |
| Show a wallet's positions | `GET /v2/portfolio/positions/{userAddress}` | 5 |
| Keyless agent access | Any paid endpoint without a key returns HTTP 402 with an x402 price; see [x402](/ai-agents/x402) | per request, priced in the 402 body |

Every request needs `x-api-key` (except x402 and `GET /v2/health`). Results from detailed-vaults and portfolio endpoints default to four networks (`base`, `mainnet`, `arbitrum`, `optimism`) and `minTvl=100000`; pass `allowedNetworks` (repeat the key per value) and `minTvl=0` to widen. Full rules: [API conventions](/api-reference/conventions). A request without a key returns HTTP 402 (x402 challenge), not 401: [Errors](/api-reference/errors).
