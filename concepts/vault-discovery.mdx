This page explains every field of a vaults.fyi vault object, what unit it is in, and what to use it for, plus the related endpoints for analytics, history and near-real-time state. Use it to build vault lists, vault detail pages and filters, or to decide which vaults to show users. Vault objects come from `GET /v2/detailed-vaults` (list, in `data[]`) and `GET /v2/detailed-vaults/{network}/{vaultId}` (one vault); both need the `x-api-key` header on `https://api.vaults.fyi`. Field names and units below were checked against the v2 OpenAPI spec and live responses captured on 2026-10-23.

Before you list vaults, know the defaults: `GET /v2/detailed-vaults` returns only `base`, `mainnet`, `arbitrum` and `optimism`, only vaults with TVL ≥ 100,000 USD (`minTvl`), sorted ascending. Pass `allowedNetworks` (repeat the key per network), `minTvl=0` and `sortOrder=desc` to change that. See [API conventions](/api-reference/conventions).

## Units used on this page

| Kind of value | Representation |
| - | - |
| APY, fees, rates, ratios | Decimal fraction: `0.0316` = 3.16% |
| Token amounts (`*Native`, `tvl.native`, capacity, balances) | Integer **string** in base units; divide by 10^`decimals` of that token |
| USD amounts (`tvl.usd`, `*Usd`, `assetPriceInUsd`) | Decimal string |
| Timestamps | Unix seconds (integer) |

## Identity

| Field | Meaning |
| - | - |
| `vaultId` | Identifier for every `{vaultId}` path parameter. Usually the vault contract address (case-insensitive); some vaults have a non-address id (for example Morpho market positions `<root>-<marketId>-<asset>`, or composite ids such as `0x5597...378c-25`). Always copy it from `GET /v2/detailed-vaults` or `GET /v2/vaults`; do not construct it. |
| `address` | Vault contract address. |
| `name` | Display name. |
| `description` | Strategy description, when provided. |
| `network.name` | Network slug (`mainnet`, `base`, ...). Use in `{network}` path params. |
| `network.chainId` | EVM chain id. Not accepted as a `network` value. |
| `network.networkCaip` | CAIP-2 id (`eip155:8453`); accepted wherever the slug is. |
| `tags` | Category tags (see [Vault tags](#vault-tags)). |
| `isAppFeatured` | Shown on app.vaults.fyi. |
| `lastUpdateTimestamp` | Last hourly index of this vault, Unix seconds. |
| `creationData.deploymentTimestamp` | Vault contract deployment time, Unix seconds. |

`vaultId` is an opaque string: copy it from a list endpoint, don't construct it. It is either the vault's contract address or `<address>-<descriptor>` for vaults that share one contract (for example lending markets or reserves). The address part is case-insensitive and returned in checksum case; the descriptor part must be passed exactly as returned. A proxy upgrade that keeps the contract address keeps the `vaultId`; a vault that migrates to a new contract gets a new `vaultId`.

## Vault tags

Tags describe the yield mechanism or exposure. A vault can have several. `Lending` is the broad parent; `Curated Lending`, `Direct Protocol Lending`, `Isolated Market` and `Shared Lending Pool` are more specific. Filter with `tags=<tag>` (repeat the key for several). Live list: `GET /v2/tags` (18 tags on 2026-10-23).

| Tag | Definition |
| - | - |
| `Basis Trading` | Products where yield is primarily generated from futures, perps, or spot/derivatives basis and funding-rate strategies. |
| `Bridging` | Products related to moving assets or liquidity across networks. |
| `CDP` | Products where yield is sourced from collateralized debt position (CDP) systems where users mint or borrow against deposited collateral. |
| `Credit` | Products with default/underwriting/counterparty risk, including private credit, structured credit, or other off-chain sources of yield. |
| `Curated Lending` | Lending exposure where a curator, risk manager, or allocator selects eligible markets, collateral, caps, or allocations. |
| `DEX-Integrated Lending` | Lending products where supplied capital directly shares a unified liquidity layer that simultaneously supports lending and DEX or trading activity. |
| `Direct Protocol Lending` | Direct supply into a protocol lending pool or market, where yield is primarily generated by borrower interest rather than a curator vault, managed strategy, credit product, or protocol savings rate. |
| `Isolated Market` | Lending market where risk is sandboxed and scoped to a specific market contract, vault, or collateral configuration rather than shared across a broad pooled lending system. |
| `Lending` | Broad parent tag for products where yield primarily comes from lending activity. Use subclass tags for more precise filtering. |
| `Liquid Staking` | Products that provide exposure to staking yield through a liquid receipt token or staking vault. |
| `Market Making` | Products where yield is generated from providing liquidity, market making, or trader flow rather than borrower interest. |
| `Protocol Savings Rate` | Yield-bearing product where the return is primarily determined by a policy-driven or governance-managed savings/rate mechanism rather than direct lending market utilization. Excludes assets that actively underwrite protocol deficits or act as first-loss capital. |
| `Risk Cover` | Products that are protected in part by cover for smart contract, protocol, slashing, custody, depeg, or other onchain risks. |
| `RWA` | Products with exposure to real-world assets or offchain financial instruments, such as tokenized treasuries, private credit, or other offchain yield sources. |
| `Safety Module` | Products where deposited assets backstop protocol risk and may be used to absorb shortfalls, underwrite liquidations, or participate in protocol protection mechanisms. |
| `Shared Lending Pool` | Lending products where supplied liquidity is pooled across multiple collateral types, exposing depositors to global or protocol-wide risk parameters rather than an isolated market configuration. |
| `Synthetic` | Products with synthetic asset construction, derivative-like backing, or engineered exposure that does not represent a simple claim on the underlying asset. |
| `Yield Aggregator` | Broad category for products that route, allocate, or compound deposits across one or more external yield sources or strategies. |

## Protocol and curator

| Field | Meaning |
| - | - |
| `protocol.protocolId` | Lowercase id from name, product and version (`morpho-v2`, `aave-collateral vault-v3`). Can contain spaces. Accepted by `allowedProtocols`. |
| `protocol.name` | Lowercase protocol name (`morpho`, `aave`). Accepted by `allowedProtocols` to match all products. |
| `protocol.displayName` | Presentation name (`Morpho`). |
| `protocol.product`, `protocol.version` | Product line and version, when applicable. |
| `protocol.protocolUrl`, `protocol.description`, `protocol.protocolLogo` | Website, description, logo URL. |
| `curator.name` | Canonical curator name; use for the `curators` filter and matching. |
| `curator.displayName` | Presentation name; fall back to `curator.name`. |
| `curator.description`, `curator.websiteUrl` | Curator info. |
| `protocolVaultUrl` | This vault on the protocol's own UI. |
| `lendUrl` | This vault on app.vaults.fyi. |

## The asset

The asset is the token users deposit and withdraw. TVL and balances are denominated in it.

| Field | Meaning |
| - | - |
| `asset.symbol`, `asset.name` | Token symbol and name. Filters `allowedAssets` / `disallowedAssets` take the **symbol** (case-insensitive); addresses are rejected as unsupported. |
| `asset.address` | Token contract address (`0x000...000` for the native token). Use as `assetAddress` in transaction calls. |
| `asset.assetCaip` | CAIP-19 asset id (`eip155:8453/erc20:0x8335...`, or `eip155:1/slip44:60` for ETH). |
| `asset.decimals` | Token decimals; convert base units with 10^decimals. |
| `asset.assetPriceInUsd` | USD price (decimal string). |
| `asset.assetGroup` | `USD`, `ETH`, `BTC`, `EURO` or `OTHER`. Use to pick a benchmark (`code=usd` / `code=eth`). |
| `asset.assetLogo` | Logo URL. |
| `additionalAssets[]` | Other tokens a multi-asset vault accepts, with the same fields. |

## The LP (share) token

Depositors receive the vault's share token, called the LP token in the API.

| Field | Meaning |
| - | - |
| `lpToken.address` | Share token address (often equal to the vault address). |
| `lpToken.symbol`, `lpToken.name` | Share token symbol and name. |
| `lpToken.tokenCaip` | CAIP-19 id of the share token. |
| `lpToken.decimals` | Share token decimals (can differ from `asset.decimals`: 18 vs 6 in the example). |

The detailed-vault object has no share-price field. Current share price: `GET /v2/nrt/vault/{network}/{vaultId}/sharePrice`. Historical share price: `GET /v2/historical/{network}/{vaultId}/sharePrice`.

## APY

All APY values are decimal fractions, net of performance and management fees, and not clamped (negative values and values above 1 occur). Method: [Calculating APY](/methodology/calculating-apy).

| Field | Meaning |
| - | - |
| `apy.<window>.base` | Yield from share-price growth over the window. |
| `apy.<window>.reward` | Yield from reward tokens over the window. |
| `apy.<window>.total` | `base + reward`. |

`<window>` is one of `1hour`, `1day`, `7day`, `30day`, `90day` (five windows). Use `7day` or `30day` for user-facing display; `1hour` and `1day` are noisy. The per-vault endpoint `GET /v2/detailed-vaults/{network}/{vaultId}/apy` returns only `1day`, `7day`, `30day` and `90day`, at the top level (no `apy` wrapper, no `1hour`).

### Composite APY for nested vaults

`apyComposite` is present only when the vault's deposit asset is another tracked vault's share token (for example an Aave market for weETH). It is absent otherwise.

| Field | Meaning |
| - | - |
| `apyComposite.vault.vaultId`, `apyComposite.vault.address` | The underlying vault. |
| `apyComposite.asset` | The underlying vault's own deposit asset. |
| `apyComposite.intrinsicApy.<window>.{base,reward,total}` | The underlying vault's own yield. |
| `apyComposite.totalApy.<window>.{base,reward,total}` | This vault's `apy.<window>` compounded with `intrinsicApy.<window>`: the full yield in terms of `apyComposite.asset`. |

Same five windows. Worked example: [Calculating APY](/methodology/calculating-apy#apycomposite-nested-vaults).

## Rewards

Each `rewards[]` entry is one reward token.

| Field | Meaning |
| - | - |
| `rewards[].asset` | Reward token (`symbol`, `address`, `decimals`, `assetPriceInUsd`, ...). |
| `rewards[].apy.<window>` | That token's reward APY for the window, as a single number (not an object). Windows `1hour`, `1day`, `7day`, `30day`, `90day`. |

Reward APYs are already included in `apy.<window>.reward`. Use `rewards[]` to attribute yield to tokens, not to add it again. Real entry (2026-10-23, trimmed): `{"asset": {"symbol": "RLUSD"}, "apy": {"1hour": 0, "1day": 0.0259, "7day": 0.0269, "30day": 0.0275, "90day": 0.0242}}`.

`additionalIncentives` is free text for non-token incentives (points, airdrops).

## TVL

| Field | Meaning |
| - | - |
| `tvl.usd` | TVL in whole USD, integer string (`"468033226"`). |
| `tvl.native` | TVL in asset base units, integer string. `"468100314975561"` / 10^6 = 468,100,314.98 USDC. |

## Reputation Score

`score.vaultScore` is the composite Reputation Score: unrounded number, higher is better (observed range 27.5–99.1).

| Field | Meaning |
| - | - |
| `score.vaultScore` | 0.45 × `protocolTvlScore` + 0.25 × `vaultTvlScore` + 0.15 × `holderScore` + 0.15 × `assetScore` − `totalScorePenalty`, floored at 0. |
| `score.protocolTvlScore`, `score.vaultTvlScore`, `score.holderScore`, `score.assetScore` | Component scores. |
| `score.networkScore` | Deprecated; 0 weight. |
| `score.totalScorePenalty` | Points deducted for flags. |
| `score.penaltyComponents[]` | `type`, `value`, `content`, `severity`, `endDate`, `resolution` for each active or decaying penalty. |

Check `score.vaultScore` client-side if you need a strict threshold. Full definition: [Reputation Score](/methodology/reputation-score).

## Holders

| Field | Meaning |
| - | - |
| `holdersData.totalCount` | Number of holders. |
| `holdersData.totalBalance` | Sum of holder balances, LP base units (÷ 10^`lpToken.decimals`). |
| `holdersData.topHolders[].address` | Holder address (largest holders; truncated list). |
| `holdersData.topHolders[].lpTokenBalance` | Holder balance, LP base units. |

## Capacity

| Field | Meaning |
| - | - |
| `maxCapacity` | Deposit cap, asset base units (integer string). `115792089237316195423570985008687907853269984665640564039457584007913129639935` (2^256−1) means uncapped. Parse with `BigInt` / Python `int`; it overflows JavaScript `Number`. |
| `remainingCapacity` | Room left under the cap, asset base units. |

## Fees

All optional; omitted when not applicable. Decimal fractions (`0.10` = 10%).

| Field | Meaning |
| - | - |
| `fees.performanceFee` | Share of yield taken. Already reflected in APY. |
| `fees.managementFee` | Annual fee on assets. Already reflected in APY. |
| `fees.depositFee`, `fees.withdrawalFee` | Charged on deposit / withdrawal. |

Show fees next to APY; do not subtract them from APY.

## Flags and warnings

| Field | Meaning |
| - | - |
| `flags[].content` | Notice text. |
| `flags[].severity` | `info`, `warning` or `critical`. |
| `flags[].endDate` | Expiry, Unix seconds. `4946619450` (year 2126) = no scheduled expiry. Expired flags are not returned. |
| `flags[].resolution` | How the issue was addressed; omitted for unresolved flags. |
| `warnings[]` | Plain-text messages of active non-`info` flags (backwards compatibility). |

Prefer `flags` (it has severity and expiry). Flags lower `score.vaultScore`. `allowVaultsWithWarnings` defaults to `true` on `GET /v2/detailed-vaults`; pass `false` to drop flagged vaults, and still check `flags` client-side.

## Transactional support

| Field | Meaning |
| - | - |
| `isTransactional` | `/v2/transactions/*` can build calls for this vault. Filter lists with `onlyTransactional=true`. |
| `transactionalProperties.depositStepsType` | `instant` or `complex`. An `instant` deposit can still be two transactions (ERC-20 approve, then deposit). |
| `transactionalProperties.redeemStepsType` | `instant` or `complex`. |
| `transactionalProperties.rewardsSupported` | Reward claims can be built. |

Read exact steps from the transaction context endpoint. See [Transaction flows](/concepts/transaction-flows).

`instant` means the deposit or redeem finishes in one step without waiting; it can still take two transactions (approve, then deposit). `complex` means the flow has a waiting period between steps, for example `request-redeem` → wait → `claim-redeem`, `start-redeem-cooldown` → wait → `redeem`, or `request-deposit` → wait → `claim-deposit`.

## Other fields

| Field | Meaning |
| - | - |
| `childrenVaults[]` | For vaults that wrap or allocate to sub-vaults: each child's `vaultId`, `address`, `asset`, `lpToken`. |
| `userEventsIndexed` | `true` if per-wallet returns and events are available (`GET /v2/portfolio/total-returns/{userAddress}/{network}/{vaultId}`, `GET /v2/portfolio/events/{userAddress}/{network}/{vaultId}`). |
| `isCorrupted` | Indexed data is known to be unreliable. Excluded by default (`allowCorrupted=false`); exclude it from production displays. |

## Advanced analytics (Beta)

| Endpoint | Use |
| - | - |
| `POST /beta/advanced-analytics` | Screen a filtered list with selected analytics sections (paginated; same filters as detailed-vaults). |
| `POST /beta/advanced-analytics/{network}/{vaultId}` | Analytics for one vault. |

The request body chooses sections; each flag must be the literal `true`:

```json
{ "select": { "maxDrawdown": true, "withdrawalPauseRatio": true, "composition": true, "utilizationRate": true, "detailedVault": true } }
```

Cost: 1 credit per request plus, per returned vault, the sum of the selected sections:

| Section | Credits per vault |
| - | -: |
| `maxDrawdown` | 2 |
| `withdrawalPauseRatio` | 2 |
| `composition` | 3 |
| `utilizationRate` | 3 |
| `detailedVault` | 3 |

Total for `n` vaults = 1 + n × (sum of selected section costs).

| Field | Meaning | Unit |
| - | - | - |
| `maxDrawdown.mdd30days`, `.mdd90days`, `.mdd365days` | Largest peak-to-trough drop in share price over 30/90/365 days | Decimal fraction |
| `withdrawalPauseRatio` | Share of time withdrawals were paused in the last two years; `null` when no pause-event source exists or history is not backfilled | 0–1 |
| `composition[].name` | Allocation target name (for example `USDe/USDC`) | — |
| `composition[].allocation` | Share of the vault allocated to it | Decimal fraction |
| `composition[].vaultId` | Target vault or market-asset id when addressable (Morpho: `<morpho>-<marketId>-<asset>`) | — |
| `composition[].network` | Target network | — |
| `composition[].asset.positionValueInAsset` | Amount allocated | Target asset base units |
| `composition[].lpToken.balanceNative` | Raw balance held in the target | Base units |
| `utilizationRate` | Share of vault assets in use (Morpho allocators: invested share; Aave/Spark: reserve utilization); `null` when unavailable | Decimal fraction |
| `detailedVault` | The full v2 detailed-vault object | — |

`utilizationRate` is returned by both the list and the single-vault endpoint when selected (verified on the list endpoint 2026-10-24).

Real composition entry (2026-10-23, `POST /beta/advanced-analytics/base/0xbeeff2490FEffa212faC2f6553682C219E6a8845`, trimmed):

```json
{ "name": "USDe/USDC", "allocation": 0.804981988286845,
  "vaultId": "0xBBBBBbbBBb9cC5e90e3b3Af64bdAF62C37EEFFCb-0x54cf9be57fdfa6457a660991907434ff9d295c465a603a50126ff647d50b7354-0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
  "lpToken": { "balanceNative": "376922765406820" },
  "asset": { "symbol": "USDC", "decimals": 6, "positionValueInAsset": "376922765406820" } }
```

Field availability depends on protocol support; treat nullable fields as "not available", not as errors. Reference: [Beta API](/api-reference/beta).

## Historical time series

`GET /v2/historical/{network}/{vaultId}` returns paginated points, **oldest first** from `fromTimestamp` (default 0 = start of history).

| Field | Meaning | Unit |
| - | - | - |
| `timestamp` | Point time | Unix seconds |
| `blockNumber` | Block of the snapshot | Integer string |
| `apy.base`, `apy.reward`, `apy.total` | APY for the window chosen by `apyInterval` | Decimal fraction |
| `tvl.usd`, `tvl.native` | TVL at that point | USD / asset base units |
| `sharePrice` | Share price at that block | Number (assets per whole share) |

Parameters: `granularity` = `1hour` (default), `1day` or `1week`; `apyInterval` = `1day`, `7day` (default), `30day` or `90day`; `fromTimestamp` / `toTimestamp` in Unix seconds (milliseconds → 400); `perPage` up to 20000. `nextPage` is absent on the last page. For the latest N points, set `fromTimestamp` = now − N × interval. Single-series variants (`/apy`, `/tvl`, `/sharePrice`) cost less. Reference: [Historical](/api-reference/historical).

## Near-real-time (NRT) state

NRT endpoints read chain state on request instead of using the hourly index. Use them for deposit previews and live dashboards.

| Endpoint | Returns | Unit |
| - | - | - |
| `GET /v2/nrt/vault/{network}/{vaultId}` | `totalSupply`, `totalAssets`, `sharePrice`, `underlyingAssetPrice` | see below |
| `GET /v2/nrt/vault/{network}/{vaultId}/sharePrice` | `sharePrice` | Number |
| `GET /v2/nrt/vault/{network}/{vaultId}/totalAssets` | `totalAssets` | Integer string, asset base units |
| `GET /v2/nrt/vault/{network}/{vaultId}/totalSupply` | `totalSupply` | Integer string, LP-token base units (`lpToken.decimals`) |
| `GET /v2/nrt/vault/{network}/{vaultId}/underlyingAssetPrice` | `underlyingAssetPrice` | Number, USD |

## Per-wallet data

Per-wallet positions, returns and events are documented in [Portfolio tracking](/concepts/portfolio-tracking). The key rule: in position objects, `asset.balanceNative` and `asset.balanceUsd` are the wallet's idle balance of the asset (repeated on every position with that asset), and the position size is `asset.positionValueInAsset` (asset base units) or `lpToken.balanceUsd` (USD). Events (`GET /v2/portfolio/events/{userAddress}/{network}/{vaultId}`) have `eventType` `deposit` or `withdrawal` only.
