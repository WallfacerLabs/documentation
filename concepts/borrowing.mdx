This page explains the vaults.fyi borrow-market API: how to list lending markets, read a wallet's supplied and borrowed positions, and build unsigned `supply`, `withdraw`, `borrow` and `repay` transactions. Use it to add borrowing to a wallet or app. These endpoints are **Beta** (`/beta/borrow/...`): they work but may change before general availability ([Versioning](/api-reference/versioning)). Auth is the same as v2: `x-api-key` header on `https://api.vaults.fyi`.

## Endpoints

| Need | Endpoint |
| - | - |
| List markets (all networks) | `GET /beta/borrow/markets/` |
| List markets on one network | `GET /beta/borrow/markets/{network}` |
| One market | `GET /beta/borrow/markets/{network}/{marketId}` |
| Market asset history | `GET /beta/borrow/markets/historical/{network}/{marketId}/{assetId}` |
| Market asset current state | `GET /beta/borrow/markets/nrt/{network}/{marketId}/{assetId}` |
| Wallet positions with debt | `GET /beta/borrow/portfolio/positions/{userAddress}` |
| Wallet position in one market | `GET /beta/borrow/portfolio/positions/{userAddress}/{network}/{marketId}` |
| Wallet position for one asset | `GET /beta/borrow/portfolio/positions/{userAddress}/{network}/{marketId}/{assetId}` |
| Wallet events for one asset | `GET /beta/borrow/portfolio/events/{userAddress}/{network}/{marketId}/{assetId}` |
| Transaction context | `GET /beta/borrow/markets/transactions/context/{userAddress}/{network}/{marketId}/{assetId}` |
| Transaction payload | `GET /beta/borrow/markets/transactions/{action}/{userAddress}/{network}/{marketId}/{assetId}?amount=<base units>` or `?all=true` |

Credit costs: see [Credits](/plans/credits).

## Identifiers

| Id | Where to get it | Format |
| - | - | - |
| `network` | — | Network slug (`base`, `mainnet`, ...). The borrow endpoints document slugs only. |
| `marketId` | `data[].marketId` from `GET /beta/borrow/markets/` | Morpho: `<marketRootAddress>-<market hash>`, for example `0xBBBBBbbBBb9cC5e90e3b3Af64bdAF62C37EEFFCb-0x3b82e29f...4bc10` |
| `assetId` | `data[].assetsData[].marketAssetId` from the markets list | Usually the token address |
| `positionId` | `data[].assets[].positionId` in positions | `eip155:<chainId>:<protocolId>:<marketId>:<assetId>` |

## Market data

Each market in `data[]` has `marketId`, `name`, `network`, `protocol`, `marketRootAddress` and `assetsData[]`. Per asset:

| Field | Meaning | Unit |
| - | - | - |
| `supplyRate`, `borrowRate` | Current supply and borrow rates | Decimal fraction (`0.0654` = 6.54%) |
| `utilizationRate` | Borrowed ÷ supplied | Decimal fraction |
| `totalSupplied`, `totalBorrowed`, `availableLiquidity`, `availableToBorrow` | Market amounts | `{usd, native}`; `native` in asset base units |
| `isCollateralEnabled` | Asset can be used as collateral | boolean |
| `assetConfig.isBorrowEnabled` | Asset can be borrowed | boolean |
| `defaultRiskParameters.maxLtv`, `.liquidationThreshold` | Risk limits | Decimal fraction |
| `defaultRiskParameters.borrowRateMultiplier` | Optional multiplier some protocols apply to the base borrow rate for this collateral | number |
| `interestRateModel` | Rate curve (for example `single-kink` with `optimalUtilization`, `slope1`, `slope2`) | decimal fractions |
| `lastUpdateTimestamp` | Last hourly snapshot | Unix seconds |

Real response (2026-10-23, `GET /beta/borrow/markets/?allowedNetworks=base&perPage=3`, trimmed to the USDC asset of one market):

```json

  "name": "Morpho cbZEC/USDC",
  "assetsData": [{
    "marketAssetId": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
    "asset": { "symbol": "USDC", "decimals": 6 },
```

List endpoints are paginated (`page`, `perPage`, `nextPage` absent on the last page). Filters: `allowedNetworks`, `allowedCollateralAssets`, `allowedBorrowAssets`, `allowedProtocols`, `minTvl`, `maxTvl` and their `disallowed*` counterparts; repeat the key for multiple values.

## Positions

`GET /beta/borrow/portfolio/positions/{userAddress}` returns `data[]` per market with `ltv`, `healthFactor` and `assets[]` (`suppliedNative`/`suppliedUsd`, `borrowedNative`/`borrowedUsd`, `collateralEnabled`, `positionId`; native amounts in asset base units).

- The wallet-wide list includes **only markets with outstanding debt**. Supply-only and collateral-only positions are omitted; read them with the single-market or single-asset endpoints.
- Asset filters and `minUsdAssetValueThreshold` (default 1 USD) can also drop a market.
- When combining results across markets, de-duplicate by `assets[].positionId`: the same economic position can appear in more than one market.
- `assets[].balanceNative` / `balanceUsd` are the wallet's idle token balance (on 2026-10-23 the USDC entry showed `78995979`, the same as the wallet's idle USDC), not the supplied or borrowed amount. Use `suppliedNative` and `borrowedNative` for position size.

## Transactions

The flow matches vault transactions: context first, then one payload per action, then sign every returned action in order.

1. `GET /beta/borrow/markets/transactions/context/{userAddress}/{network}/{marketId}/{assetId}`. The response has `currentSupplyStep`/`supplySteps`, `currentWithdrawStep`/`withdrawSteps`, `currentBorrowStep`/`borrowSteps` and `currentRepayStep`/`repaySteps`. Each step lists the transactions it produces, for example `["approve","supply"]`. Some protocols add `enableCollateral` or `enableController`; do not hard-code approve + supply.
2. `GET /beta/borrow/markets/transactions/{action}/{userAddress}/{network}/{marketId}/{assetId}` with `action` = `supply`, `withdraw`, `borrow` or `repay`, and either:
   - `amount`: integer string in the asset's **base units** (1 USDC = `1000000`), or
   - `all=true`: withdraw or repay the full amount.
3. The response is `{currentActionIndex, actions[]}` with `actions[].tx = {to, chainId, data, value?}`. Sign and send each action in order and wait for each receipt.

Vault actions (`deposit`, `redeem`) are rejected with HTTP 400 listing `supply`, `withdraw`, `borrow`, `repay`. Here `withdraw` means withdrawing supplied assets from a borrow market; for vaults the equivalent action is `redeem`.

Real response (2026-10-23, `supply` with `amount=1000000`, data trimmed):

```json
{ "currentActionIndex": 0,
  "actions": [
    { "name": "Approve USDC for Morpho cbZEC/USDC borrow market",
      "tx": { "to": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913", "chainId": 8453, "data": "0x095ea7b3...000f4240" } },
    { "name": "Supply USDC to Morpho cbZEC/USDC borrow market",
      "tx": { "to": "0xBBBBBbbBBb9cC5e90e3b3Af64bdAF62C37EEFFCb", "chainId": 8453, "data": "0xa99aad89...fffc69deb" } } ] }
```

### Safety before signing a borrow or withdraw

- Recompute the health factor the action would produce from the positions response and refuse actions that would push it below your threshold.
- Check `chainId`, `to`, and that the amount does not exceed the wallet balance (supply, repay) or the available amount (borrow, withdraw).
- Require explicit user confirmation for borrows. Liquidation risk is the user's.

See [Transaction safety](/ai-agents/transaction-safety).

## Errors

| Situation | Result |
| - | - |
| Unknown market | 404 `{"error":"Not Found","message":"Borrow market ... not found"}` (no `statusCode` field) |
| Vault action such as `deposit` | 400 listing the four borrow actions |
| No `x-api-key` | Borrow endpoints need an API key (they are not sold over x402) |
