# Beta
Source: https://docs.vaults.fyi/api-reference/beta

> Features in testing. More stable than Alpha, but may still change before general availability.

> [!WARNING]
>
> Beta endpoints are functional and tested but not yet part of the stable API. Interfaces may change before general availability. Not recommended for production use without monitoring.

Beta features are accessible using your existing API key. The endpoints below cover product areas that are being validated before general availability.

Where an endpoint supports `allowedProtocols` or `disallowedProtocols`, each value may be either a broad protocol name or a full [protocol ID](/concepts/supported-protocols.md#protocol-names-and-ids) for one product and version.

## Solana vaults

Build Solana/SVM vault integrations alongside the EVM vault API surface. These endpoints cover Solana vault discovery, detailed vault data, wallet positions and events, idle assets, and ready-to-sign transaction construction.

Detailed vault responses can include an optional `lpToken` object with `address` (the LP-token mint), `tokenCaip` (its CAIP-19 identifier), `name`, `symbol`, and `decimals`. The object is omitted when the required metadata is unavailable.

Idle-asset responses include token `name` and `symbol`, plus `assetLogo` where available, alongside the address, decimals, and balance. For single-asset lookups, unavailable names and symbols can be empty strings.

| Capability | How to call | Required inputs |
| - | - | - |
| List SVM vault identifiers | `GET /beta/svm/vaults` | None |
| List SVM detailed vaults | `GET /beta/svm/detailed-vaults` | None. Optional query filters include `page`, `perPage`, `assetSymbol`, `allowedAssets`, `disallowedAssets`, `allowedProtocols`, `disallowedProtocols`, `allowedAssetMints`, `disallowedAssetMints`, `minTvl`, `maxTvl`, `minApy`, `maxApy`, `sortBy`, and `sortOrder` |
| Fetch one SVM detailed vault | `GET /beta/svm/detailed-vaults/{vaultAddress}` | Path: `vaultAddress` |
| List SVM positions for a wallet | `GET /beta/svm/portfolio/positions/{userAddress}` | Path: `userAddress`. Optional query: `apyInterval`, `minUsdAssetValueThreshold` |
| List SVM portfolio events for a wallet | `GET /beta/svm/portfolio/events/{userAddress}` | Path: `userAddress` |
| List SVM portfolio events for one vault | `GET /beta/svm/portfolio/events/{userAddress}/{vaultAddress}` | Path: `userAddress`, `vaultAddress` |
| List idle SVM assets for a wallet | `GET /beta/svm/portfolio/idle-assets/{userAddress}` | Path: `userAddress`. Optional query: `allowedAssets`, `disallowedAssets` |
| Fetch one idle SVM asset | `GET /beta/svm/portfolio/idle-assets/{userAddress}/{assetAddress}` | Path: `userAddress`, `assetAddress` |
| Check balances and limits before building an SVM transaction | `GET /beta/svm/transactions/context/{userAddress}/{vaultAddress}` | Path: `userAddress`, `vaultAddress` |
| Build a ready-to-sign SVM transaction | `GET /beta/svm/transactions/{action}/{userAddress}/{vaultAddress}` | Path: `action`, `userAddress`, `vaultAddress`. Query: `assetAddress`, plus `amount` when the action requires an amount. Optional query: `simulate` |

### Reading SVM position values

`GET /beta/svm/portfolio/positions/{userAddress}` returns positions in `data`. Each position's `asset` object includes:

| Field | Meaning |
| - | - |
| `balanceNative` | Current position value in underlying-asset base units, as an integer string |
| `positionValueInAsset` | Optional explicit position-value field, currently equal to `balanceNative` |
| `balanceUsd` | Current position value in USD, as a string |
| `unclaimedNative` | Pending-redemption amount in underlying-asset base units, separate from the current position value |
| `unclaimedUsd` | Pending-redemption value in USD, as a string |
| `decimals` | Underlying-asset precision used to convert base units to display units |

For example, a `positionValueInAsset` of `"1250000"` with `decimals: 6` represents 1.25 underlying tokens. Do not add `positionValueInAsset` to `balanceNative`: they describe the same balance. If the optional field is absent, use `balanceNative`. These are underlying-asset amounts, not LP-token share amounts.

### Building SVM transactions

SVM transaction responses return one or more actions with a Solana transaction object at `actions[].tx.transaction`. The value is a base64-encoded serialized Solana transaction ready for wallet signing. Passing `simulate=true` can add a `simulation` object with status plus token amounts expected to be spent or received.

## Borrow markets

Build borrow dashboards and account-health views against one borrow market model instead of wiring separate protocol-specific routes. Use these endpoints for market discovery, historical rates, user positions, user events, and ready-to-sign borrow transaction payloads.

Supported Aave V4 Standard Spoke markets on Ethereum use this same normalized surface for market data, wallet positions, and supply, withdraw, borrow, and repay transaction payloads.

| Capability | How to call | Required inputs |
| - | - | - |

Optional query filters include `page`, `perPage`, `allowedNetworks`, `disallowedNetworks`, `allowedCollateralAssets`, `disallowedCollateralAssets`, `allowedBorrowAssets`, `disallowedBorrowAssets`, `allowedProtocols`, `disallowedProtocols`, `minTvl`, and `maxTvl` |
| List borrow markets on one network | `GET /beta/borrow/markets/{network}` | Path: `network`. Optional query filters include `page`, `perPage`, `allowedCollateralAssets`, `disallowedCollateralAssets`, `allowedBorrowAssets`, `disallowedBorrowAssets`, `allowedProtocols`, `disallowedProtocols`, `minTvl`, and `maxTvl` |
| Fetch one borrow market | `GET /beta/borrow/markets/{network}/{marketId}` | Path: `network`, `marketId` |
| Fetch near-real-time borrow market asset data | `GET /beta/borrow/markets/nrt/{network}/{marketId}/{assetId}` | Path: `network`, `marketId`, `assetId` |
| Fetch historical borrow market data | `GET /beta/borrow/markets/historical/{network}/{marketId}/{assetId}` | Path: `network`, `marketId`, `assetId` |
| List borrow positions for a wallet | `GET /beta/borrow/portfolio/positions/{userAddress}` | Path: `userAddress`. Optional query: `allowedNetworks`, `disallowedNetworks`, `allowedAssets`, `disallowedAssets`, `minUsdAssetValueThreshold`, `sortBy`, `sortOrder` |

### Reading borrow positions

`GET /beta/borrow/portfolio/positions/{userAddress}` lists markets with outstanding debt, not every supply-only or collateral-only position. A market must retain an asset with nonzero `borrowedNative` after asset and USD-value filtering to appear in the list. Filtering out the debt asset can therefore remove the entire market, including its collateral.

Use the single-market or asset-level position endpoints when inspecting a known position, including one without debt. When aggregating balances across markets, use `assets[].positionId` to avoid counting the same underlying position more than once.

### Building borrow transactions

Fetch transaction context first and use the returned `supplySteps`, `withdrawSteps`, `borrowSteps`, or `repaySteps`. Their action lists depend on the protocol and collateral configuration, and may include `enableCollateral` or `enableController` alongside approval and supply/withdraw/borrow/repay actions. Do not hard-code a universal approval-and-supply sequence.

Borrow market responses expose `assetsData[].marketAssetId`. Pass that value as `{assetId}` when chaining from market discovery into historical data, portfolio events, asset-level positions, or transaction endpoints.

Risk-parameter objects can include `borrowRateMultiplier`, the collateral risk multiplier applied to the base borrow rate. The field is optional because it is only returned when the underlying protocol supplies this parameter.

## Advanced analytics

Request heavier per-vault analytics only when your product needs them. Selectable analytics sections include max drawdown, withdrawal pause ratio, composition, utilization rate, and the full V2 detailed-vault payload where supported.

| Capability | How to call | Required inputs |
| - | - | - |
| List advanced vault analytics using selected analytics sections | `POST /beta/advanced-analytics` | JSON body: `select`. Optional query filters include detailed-vault-style filters such as `allowedNetworks`, `disallowedNetworks`, `allowedAssets`, `disallowedAssets`, `allowedProtocols`, `disallowedProtocols`, `minTvl`, `maxTvl`, `minApy`, `maxApy`, `minVaultScore`, `tags`, `curators`, `onlyTransactional`, `onlyAppFeatured`, `allowCorrupted`, `allowVaultsWithWarnings`, `sortBy`, `sortOrder`, `page`, and `perPage` |
| Fetch advanced analytics for one vault | `POST /beta/advanced-analytics/{network}/{vaultId}` | Path: `network`, `vaultId`. JSON body: `select` |

Each request costs 1 base credit. The remaining cost scales with the number of items returned and the fields included for each item:

| Selected field | Credits per returned item |
| - | -: |
| `maxDrawdown` | 2 |
| `detailedVault` | 3 |
| `withdrawalPauseRatio` | 2 |
| `composition` | 3 |
| `utilizationRate` | 3 |

The per-item costs are cumulative. For example, a request that returns 10 items with `maxDrawdown` and `composition` costs `1 + (10 × (2 + 3)) = 51` credits.

## Fixed Term (Pendle)

Add fixed-term yield market support for Pendle-backed opportunities. Use these endpoints to discover and compare active markets, retrieve detailed market data, preview transaction context, and generate swap-in or swap-out transactions.

| Capability | How to call | Required inputs |
| - | - | - |
| List fixed-term markets | `GET /beta/fixed-term/` | None. Optional query filters include `page`, `perPage`, `allowedAssets`, `disallowedAssets`, `allowedProtocols`, `disallowedProtocols`, `allowedNetworks`, `disallowedNetworks`, `minTvl`, `search`, `sortBy`, and `sortOrder` |
| Fetch fixed-term detailed vault data | `GET /beta/fixed-term/detailed/{network}/{vaultId}` | Path: `network`, `vaultId` |

Fixed-term market discovery costs 1 base credit plus 3 credits per returned market. For example, 10 returned markets cost 31 credits.
