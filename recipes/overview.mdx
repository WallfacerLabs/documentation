This page lists the vaults.fyi recipes: complete, runnable examples that solve one integration task end to end, each in curl, Python and TypeScript. Pick the recipe that matches your task; each page stands alone with prerequisites, credit cost, steps, real output and pitfalls.

Every snippet on these pages was executed against the live API on 2026-10-23, read-only, with the public address `0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045`. Transaction recipes build and verify unsigned payloads and show how to sign with viem; **no transaction was signed or broadcast**. All REST calls use `https://api.vaults.fyi` with the header `x-api-key: $VAULTSFYI_API_KEY`.

## Rules every recipe follows

- **Auth:** `x-api-key` header on REST. Without it, v2 endpoints return 402 (x402 payment challenge), not 401.
- **Units:** APY is a decimal fraction, net of fees. Token amounts are base-unit integer strings. Timestamps are Unix seconds.
- **Defaults:** list and portfolio endpoints search only base, mainnet, arbitrum and optimism unless you pass `allowedNetworks`; `/v2/detailed-vaults` also defaults to `minTvl=100000` and `sortOrder=asc`.
- **Arrays:** repeat the query key (`allowedNetworks=base&allowedNetworks=arbitrum`).
- **Pagination:** `nextPage` is absent on the last page.
- **Soft errors:** a 200 can carry `errors.unsupported*`; treat non-empty lists as errors.
- **Transactions:** context first, verify every action, send in order, never let an API or agent hold a private key.
