The Vaults.fyi API supports the [x402 payment protocol](https://www.x402.org/) (v2) for keyless, pay-per-request access using USDC on Base. Instead of managing API keys, your agent pays for each request directly from its onchain wallet. This makes x402 ideal for autonomous agents and systems that already hold assets onchain.

## How it works

1. Send a request without an API key — the `x-402-auth` header is optional.
2. Receive a `402 Payment Required` response containing payment details in the JSON body and `payment-required` header, including the current `accepts[].amount`.
3. Sign a USDC payment on Base using your agent's wallet.
4. Resend the original request with the `payment-signature` proof header attached.
5. Receive a `200` response with the requested data and a receipt in the `payment-response` header.

The [`@x402/fetch`](https://www.npmjs.com/package/@x402/fetch) JavaScript and [`x402`](https://pypi.org/project/x402/) Python libraries handle this payment flow automatically, so you don't need to implement the handshake manually. Use v2-compatible clients; the legacy `X-Payment` header and `maxAmountRequired` field no longer apply.

If you send `x-api-key`, the API uses API-key authentication and billing instead. An invalid API key does not fall back to x402.

## Quick start

Install the x402 client library and make your first request. Set `PRIVATE_KEY` in your environment and fund that wallet with USDC on Base. These examples use the fixed-price `/v2/vaults` endpoint and make a real payment, capped at 1 USDC per request:

<CodeGroup>

```javascript javascript
// pnpm add @x402/core@2.26.0 @x402/evm@2.26.0 @x402/fetch@2.26.0 viem
import { x402Client } from "@x402/core/client";
import { ExactEvmScheme } from "@x402/evm/exact/client";
import { wrapFetchWithPayment } from "@x402/fetch";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount(process.env.PRIVATE_KEY);
const client = new x402Client()
  .register("eip155:8453", new ExactEvmScheme(account))
  .registerPolicy((_version, requirements) =>
    requirements.filter((payment) => BigInt(payment.amount) <= 1_000_000n),
  );
const fetchWithPayment = wrapFetchWithPayment(fetch, client);

const response = await fetchWithPayment("https://api.vaults.fyi/v2/vaults");
if (!response.ok) throw new Error(`API returned ${response.status}`);
console.log(await response.json());
```

```python python
# pip install "x402[requests,evm]==2.26.0"
import os
from eth_account import Account
from x402 import x402ClientSync
from x402.http.clients import x402_requests
from x402.mechanisms.evm import EthAccountSigner
from x402.mechanisms.evm.exact import ExactEvmScheme

account = Account.from_key(os.environ["PRIVATE_KEY"])
client = x402ClientSync().register(
    "eip155:8453", ExactEvmScheme(EthAccountSigner(account))
)
client.register_policy(
    lambda _version, requirements: [
        p for p in requirements if int(p.amount) <= 1_000_000
    ]
)

with x402_requests(client) as session:
    response = session.get("https://api.vaults.fyi/v2/vaults")
    response.raise_for_status()
    print(response.json())
```

</CodeGroup>

For a complete working example, see the [Agentic DeFi repo](https://github.com/WallfacerLabs/agentic_defi).

## Pricing

All prices are in USDC on Base, charged per request. Payment is in USDC raw units (6 decimals) — for example, `5000` = $0.005 USDC. The `402` response always contains the current `accepts[].amount`. Prices are subject to change.

| Price  | Endpoints |
| ------ | --------- |
| $0.005 | `/v2/networks`, `/v2/vaults`, `/v2/tags`, `/v2/assets`, `/v2/curators` |
| $0.01  | `/v2/detailed-vaults/{network}/{vaultId}/apy`, `/v2/detailed-vaults/{network}/{vaultId}/tvl` |
| $0.02  | `/v2/detailed-vaults/{network}/{vaultId}`, `/v2/portfolio/positions/{userAddress}` |
| $0.025 | `/v2/portfolio/best-deposit-options/{userAddress}`, `/v2/portfolio/idle-assets/{userAddress}`, `/v2/portfolio/best-vault/{userAddress}` |
| $0.05  | `/v2/transactions/*`, `/v2/transactions/rewards/claim/{userAddress}` |
| $0.75  | `/v2/detailed-vaults` (paginated list of all vaults) |
| Free   | `/v2/health` |

All paginated v2 endpoints and beta advanced analytics support `upto`: authorize the quoted maximum, then pay for actual returned usage. Per-item endpoints quote using `perPage`; the basic vault and asset lists retain their flat charge. Empty successful results still incur the base charge. Best deposit options intentionally remain fixed-price with `exact`.

Every `upto` endpoint also accepts `exact` at the quoted maximum. Choosing `exact` pays that full amount even when fewer items or analytics sections are returned, with no refund of the difference. This intentional overpayment supports exact-only clients, including the examples above.

To pay for actual usage instead, register an `upto`-capable client (for example, `UptoEvmScheme` from `@x402/evm/upto/client` in JavaScript) and approve USDC to Permit2 before paying. Approval may require Base ETH for gas. Batch-capable clients can alternatively use `batch-settlement` when advertised in `accepts`.

<Note>
  x402 supports paid v2 endpoints, including `/v2/historical/*`, and the beta advanced-analytics endpoints. See [credit costs](/plans/credits) for historical and other endpoint prices. Other beta, alpha, and legacy v1 endpoints require an API key; [sign up](https://portal.vaults.fyi/signup) to get one.
</Note>
