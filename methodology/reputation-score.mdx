This page defines the vaults.fyi Reputation Score, maps each part of it to a response field, and shows how to filter vaults by it safely. Use it when you screen vaults for users or need to explain a score. The Reputation Score is one number per vault in the field `score.vaultScore`, returned by `GET /v2/detailed-vaults` and `GET /v2/detailed-vaults/{network}/{vaultId}` (REST, `x-api-key` header). Higher means a longer, larger track record. It is a track-record signal, not a full risk rating.

## Definition

`score.vaultScore` is a weighted sum of four component scores minus the current flag penalty, floored at zero:

```text
score.vaultScore = max(0,
    0.45 * score.protocolTvlScore
  + 0.25 * score.vaultTvlScore
  + 0.15 * score.holderScore
  + 0.15 * score.assetScore
  - score.totalScorePenalty
)
```

This formula reproduces `score.vaultScore` exactly (to floating-point precision) for every one of the 62 distinct vaults with a `score` object in the 2026-10-23 live captures.

| Component | Weight | Response field | What it measures |
| - | -: | - | - |
| Protocol integrity | 45% | `score.protocolTvlScore` | How much TVL the protocol has secured and for how long (log-scaled, so a few huge protocols do not dominate). $500M held for two years scores higher than $500M held for a week. |
| Pool diagnostics | 25% | `score.vaultTvlScore` | The same TVL-over-time measure applied to this specific vault or pool. Aave v3 USDT ($5B) and Aave v3 pyUSD ($12M) on mainnet score differently. |
| Community adoption | 15% | `score.holderScore` | Number and distribution of holders; more unique holders means less concentration. |
| Underlying asset reliability | 15% | `score.assetScore` | Peg stability, ±2% onchain liquidity depth and CEX/DEX volume of the deposit asset. |
| Flag penalty | subtracted | `score.totalScorePenalty` | Point deduction from active or decaying flags (see below). |
| Network (deprecated) | 0% | `score.networkScore` | Returned for backwards compatibility only. It is not part of the score. |

### Range

`score.vaultScore` and each component range from 0 to 100. The API does not round them (for example `81.72160425089307`). Observed values on 2026-10-23: `score.vaultScore` from 27.5 to 99.1. Because the weights sum to 1 and the result is floored at 0, `score.vaultScore` is at most the maximum component value.

The API always returns a score, including for young vaults. app.vaults.fyi shows "Not Rated" for vaults younger than 90 days or with no holder score; apply the same check if you filter on score.

Real response from `GET /v2/detailed-vaults/base/0xbeeff2490FEffa212faC2f6553682C219E6a8845` (2026-10-23, trimmed to `score`):

## Flag penalties

vaults.fyi attaches flags to vaults for incidents and risks (for example compromised keys or bad debt). Flags appear in `flags[]` (`content`, `severity`, `endDate`, optional `resolution`), and `warnings` repeats the text of active non-`info` flags.

- Flags reduce the score through `score.totalScorePenalty`: 25 points for a `warning` flag, 50 for a `critical` flag, 0 for `info`. Only the single largest penalty applies; penalties do not stack.
- `score.penaltyComponents[]` lists the penalty that applies (the largest one): `type` (`flag`), `value` (points deducted now), `content`, `severity`, `endDate` (Unix seconds) and optional `resolution`.
- While a flag is active the full penalty applies. After its `endDate` the penalty fades to zero over one year, so the score recovers gradually. A resolved flag carries no penalty.
- `endDate` `4946619450` (year 2126) means the flag has no scheduled expiry.

Observed on 2026-10-23: a `critical` flag (Swell, compromised hot keys) carried `score.totalScorePenalty` = 50.


## What the score does not cover

- Smart-contract audits, governance risk, upgradeability and admin-key exposure.
- Security of the blockchain the vault runs on (network score has 0 weight).
- Risks vaults.fyi has not flagged.

A long-lived risky protocol can score well; a well-audited new protocol scores low until it builds a track record. Use the score for programmatic screening and use risk reports (for example LlamaRisk, Chaos Labs, Gauntlet) for due diligence.

## Filtering by score

The list endpoints accept `minVaultScore` (number). Use it to narrow the result set. Check `score.vaultScore` client-side if you need a strict threshold. Also exclude flagged vaults: `allowVaultsWithWarnings` defaults to `true` on `GET /v2/detailed-vaults`.

```bash
curl -s "https://api.vaults.fyi/v2/detailed-vaults?allowedNetworks=base&allowedAssets=USDC&minVaultScore=70&allowVaultsWithWarnings=false&sortBy=apy7day&sortOrder=desc&perPage=50" \
  -H "x-api-key: $VAULTSFYI_API_KEY"
```

```python
import os, requests

MIN_SCORE = 70
r = requests.get(
    "https://api.vaults.fyi/v2/detailed-vaults",
    headers={"x-api-key": os.environ["VAULTSFYI_API_KEY"]},
    params={"allowedNetworks": "base", "allowedAssets": "USDC", "minVaultScore": MIN_SCORE,
            "allowVaultsWithWarnings": "false", "sortBy": "apy7day", "sortOrder": "desc", "perPage": 50},
)
r.raise_for_status()
safe = [v for v in r.json()["data"]
        if v["score"]["vaultScore"] >= MIN_SCORE   # client-side check for a strict threshold
        and not v.get("flags") and not v.get("isCorrupted")]
```

```typescript
const MIN_SCORE = 70;
const url = new URL("https://api.vaults.fyi/v2/detailed-vaults");
url.search = new URLSearchParams({
  allowedNetworks: "base", allowedAssets: "USDC", minVaultScore: String(MIN_SCORE),
  allowVaultsWithWarnings: "false", sortBy: "apy7day", sortOrder: "desc", perPage: "50",
}).toString();
const body = await (await fetch(url, { headers: { "x-api-key": process.env.VAULTSFYI_API_KEY! } })).json();
const safe = body.data.filter((v: any) =>
  v.score.vaultScore >= MIN_SCORE && !(v.flags?.length) && !v.isCorrupted);
```

Choose the threshold for your users: consumer wallets typically use 70 or higher; tools for sophisticated users may go lower to include newer vaults.

Note that `GET /v2/detailed-vaults` covers only `base`, `mainnet`, `arbitrum` and `optimism` and vaults with TVL ≥ 100,000 USD by default; pass `allowedNetworks` (repeat the key per network) and `minTvl` to change that. See [API conventions](/api-reference/conventions).
