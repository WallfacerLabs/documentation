This page explains how vaults.fyi computes APY and how APY appears in API responses. Use it when you need to interpret, display or compare APY values, or to explain why vaults.fyi differs from a protocol's own UI. In short: APY is the realized yield from onchain share-price changes over a trailing window, net of fees, returned as a decimal fraction (`0.0316` = 3.16%) in the object `apy.<window>.{base,reward,total}`.

## How APY appears in the API

| Rule | Detail |
| - | - |
| Unit | Decimal fraction. `0.0316` = 3.16%. Multiply by 100 to display a percentage. |
| Net of fees | Performance and management fees are already deducted. The `fees` object is for display only; do not subtract it again. |
| Not clamped | Values can be negative or very large. A 7-day APY of `1522.9882` (152,299%) and `-0.1769` were both observed on 2026-10-23. Screen outliers before display. |
| Shape | `apy.<window>.base`, `apy.<window>.reward`, `apy.<window>.total`, where `total = base + reward`. |
| Windows on detailed-vault responses | `1hour`, `1day`, `7day`, `30day`, `90day` (`GET /v2/detailed-vaults`, `GET /v2/detailed-vaults/{network}/{vaultId}`). |
| Windows on `GET /v2/detailed-vaults/{network}/{vaultId}/apy` | `1day`, `7day`, `30day`, `90day` at the top level (no `1hour`, no `apy` wrapper). |
| Single-window responses | Portfolio endpoints and `GET /v2/historical/...` return one window as `apy.{base,reward,total}`; choose it with `apyInterval` (`1day`, `7day`, `30day`, `90day`; default `7day`). |
| Sorting | `sortBy=apy1day`, `apy7day`, `apy30day` or `apy90day` on `GET /v2/detailed-vaults`. `sortOrder` defaults to `asc`. |

Older docs and SDK examples used flat names such as baseApy, rewardApy, apy7d or apy30d; those fields do not exist in any response. Read `apy.<window>.base`, `apy.<window>.reward` and `apy.<window>.total`. The names `totalApy` and `intrinsicApy` exist only inside `apyComposite` (see below).

Real response from `GET /v2/detailed-vaults/base/0xbeeff2490FEffa212faC2f6553682C219E6a8845` (2026-10-23, trimmed to `apy`):

```json
{
  "apy": {
    "1hour": { "base": 0.0317, "reward": 0, "total": 0.0317 },
    "1day":  { "base": 0.0317, "reward": 0, "total": 0.0317 },
    "7day":  { "base": 0.0316, "reward": 0, "total": 0.0316 },
    "30day": { "base": 0.0305, "reward": 0, "total": 0.0305 },
    "90day": { "base": 0.0293, "reward": 0, "total": 0.0293 }
  }
}
```

Read it in code:

```python
seven_day_pct = vault["apy"]["7day"]["total"] * 100   # 3.16
```

```typescript
const sevenDayPct = vault.apy["7day"].total * 100;   // 3.16
```

## Share-price method

Every yield-bearing vault issues shares. As the vault earns, the assets behind each share grow, so the share price rises. vaults.fyi reads share price from chain every hour and derives APY from its change over the window.

```
share price   = total assets / total shares
interest rate = (current share price / previous share price) - 1
```

For vaults that compound automatically:

```
APY = (1 + interest rate) ^ (year / time) - 1
```

For vaults that pay simple (non-compounding) interest:

```
APY = interest rate × (year / time)
```

`time` is the window length in seconds; `year` is 31,536,000 seconds.

How share price is read for each vault type (ERC-4626, rebasing, LST, staking, RWA) is in [Indexing onchain data](/methodology/indexing-onchain-data).

## Trailing windows, not spot rates

A spot rate captures one instant and is skewed by liquidity events, large deposits and the timing of reward distributions. Trailing windows show what depositors actually earned.

| Window | Use |
| - | - |
| `1hour`, `1day` | Most responsive; noisy. Dashboards and anomaly detection. |
| `7day` | Default for most endpoints (`apyInterval` default). Good for user-facing display. |
| `30day`, `90day` | Most stable; slow to reflect strategy changes. |

## Adjusting for TVL changes

When TVL swings within a window, a simple average misstates yield. vaults.fyi weights each observation by the minimum TVL of two consecutive data points, which avoids inflating yield during large inflows:

```
weight_t      = min(TVL_t, TVL_(t-1))
interest rate = Σ((share_price_t / share_price_(t-1)) × weight_t) / Σ(weight_t) - 1
```

This matters most for new vaults and vaults with sudden large deposits.

## Base yield and reward yield

- `apy.<window>.base`: yield from share-price growth (lending interest, strategy returns, staking).
- `apy.<window>.reward`: yield from reward tokens distributed on top, converted into the deposit asset.
- `apy.<window>.total`: `base + reward`.

Reward APY is calculated per window as follows:

1. Compute reward tokens distributed per deposited token, using a TVL-weighted average emission rate.
2. Compute the time-weighted average price of the reward token in deposit-asset terms.
3. Convert accumulated rewards into deposit-asset value with that price.
4. Compare with the initial deposit to get APY.

Per-token reward rates are in the `rewards` array (`rewards[].asset`, `rewards[].apy.<window>`, decimal fractions). They are already included in `apy.<window>.reward`; do not add them again.

If a vault's `total` is higher than its share-price growth suggests, compare `apy.<window>.base` with `apy.<window>.reward`: the difference comes from reward tokens.

## apyComposite: nested vaults

`apyComposite` is present only when a vault's deposit asset is itself the share (LP) token of another vault that vaults.fyi tracks, for example an Aave v3 market whose deposit asset is weETH. It is absent on all other vaults; check for it before reading.

| Field | Meaning | Unit |
| - | - | - |
| `apyComposite.vault.vaultId` | The underlying vault whose share token this vault accepts | — |
| `apyComposite.asset` | The underlying vault's own deposit asset | — |
| `apyComposite.intrinsicApy.<window>.{base,reward,total}` | **The yield of the underlying vault (`apyComposite.vault`) on its own**, before this vault adds anything | decimal fraction |
| `apyComposite.totalApy.<window>.{base,reward,total}` | This vault's `apy.<window>` compounded with `intrinsicApy.<window>`: the full yield a depositor earns in terms of `apyComposite.asset` | decimal fraction |

Windows are `1hour`, `1day`, `7day`, `30day`, `90day`.

Real example (`GET /v2/detailed-vaults?...`, Aave v3 weETH on mainnet, 2026-10-23, trimmed): the Aave market itself earned 0 over 7 days, the weETH vault underneath earned 2.24%, so the compounded total is 2.24%.

```json
{
  "name": "Aave v3 weETH",
  "apy": { "7day": { "base": 0, "reward": 0, "total": 0 } },
  "apyComposite": {
    "vault": { "vaultId": "0xCd5fE23C85820F7B72D0926FC9b05b43E359b7ee" },
    "asset": { "symbol": "ETH", "decimals": 18 },
    "intrinsicApy": { "7day": { "base": 0.0224, "reward": 0, "total": 0.0224 } },
    "totalApy":     { "7day": { "base": 0.022399999999999975, "reward": 0, "total": 0.022399999999999975 } }
  }
}
```

```python
comp = vault.get("apyComposite")
full_7d = comp["totalApy"]["7day"]["total"] if comp else vault["apy"]["7day"]["total"]
```

## Frequently asked questions about APY

### Why does vaults.fyi APY differ from what a protocol reports?

Protocol UIs often show forward-looking or instantaneous rates from their interest-rate model. vaults.fyi reports trailing realized APY from what share prices actually did. The two differ when rates changed recently or when the protocol's compounding assumption does not match how yield accrues.

### Why does APY spike for some vaults?

Some vaults, especially liquid staking tokens and Yearn-style strategies, post earnings in batches. When a batch lands, the share price jumps and short windows (`1hour`, `1day`) spike. Use `7day` or `30day` for these vaults.

### Do vault types need special share-price logic?

Yes. Rebasing tokens (such as Aave aTokens) grow balances instead of share price; staking vaults (such as StakeWise) separate principal and reward tokens; RWA vaults use oracle prices. See [Indexing onchain data](/methodology/indexing-onchain-data).

### How fresh is APY?

APY is recomputed from the hourly index. Each vault's `lastUpdateTimestamp` (Unix seconds) shows the last index time.
