This page answers "how many credits will this request cost?" for every vaults.fyi REST endpoint. It explains the charging model, lists each endpoint by its exact path, works through examples, and shows how to cut usage. Use it to estimate spend before you build a polling loop or let an agent call the API.

Credits are also called Compute Units (CUs). Subscription plans include a monthly credit allowance; pay-as-you-go charges a flat **$0.002 per credit**. Plan prices and allowances are on [Plans and pricing](/plans/overview). All requests use `https://api.vaults.fyi` with the header `x-api-key: $VAULTSFYI_API_KEY`.

## How a request is charged

Each request costs:

```
credits = base cost per call + (cost per item × number of items returned)
```

- **Base cost per call** is charged on every request to that endpoint, whatever it returns.
- **Cost per item** applies only to the list and time-series endpoints that show one below. An item is one element of the response `data` array: one vault, one market, or one historical data point.
- The charge is per request, so each page of a paginated list pays the base cost again.

- Only requests that return HTTP 200 are charged. A request that returns 400, 404, 500 or any other non-200 status costs no credits (and an x402 payment for it is not settled).

## Worked examples

| Request | Calculation | Credits | Pay-as-you-go |
| - | - | -: | -: |
| `GET /v2/detailed-vaults?perPage=50` returning 50 vaults | 1 + 50 × 3 | 151 | $0.302 |
| `GET /v2/detailed-vaults/{network}/{vaultId}/apy` (one vault's `1day`–`90day` APY) | 1 | 1 | $0.002 |
| `GET /v2/detailed-vaults/{network}/{vaultId}` (full detail of one vault) | 3 | 3 | $0.006 |
| `GET /v2/historical/{network}/{vaultId}` for 30 days at the default `granularity=1hour`, `perPage=720` (720 points, one call) | 3 + 720 × 3 | 2,163 | $4.326 |
| The same 30 days with `granularity=1day` (30 points) | 3 + 30 × 3 | 93 | $0.186 |
| The same 30 days of APY only: `GET /v2/historical/{network}/{vaultId}/apy?granularity=1day` | 1 + 30 × 1 | 31 | $0.062 |
| `POST /beta/advanced-analytics` returning 10 vaults with `maxDrawdown` and `composition` | 1 + 10 × (2 + 3) | 51 | $0.102 |

These totals are calculated from the documented costs; the API does not return a per-request credit count.

## How to spend fewer credits

- **Need IDs, not metrics?** `GET /v2/vaults` costs 1 credit per call however many vaults it returns (up to `perPage=5000`), while `/v2/detailed-vaults` costs 3 per vault.
- **One known vault?** Use the single-vault endpoints: `/apy` or `/tvl` (1 credit) instead of the full detail (3) or a list.
- **Filter on the server.** Narrow `/v2/detailed-vaults` with `allowedNetworks`, `allowedAssets`, `minTvl` and a small `perPage`, because every returned vault costs 3.
- **Historical data:** use `granularity=1day` or `1week` instead of the default `1hour`, a narrow `fromTimestamp`/`toTimestamp` window, and the single-series endpoints (`/apy`, `/tvl`, `/sharePrice`: 1 per point) instead of the combined endpoint (3 per point).
- **Cache.** Indexed data refreshes about hourly, so polling the same list more often than that mostly re-buys the same data.

## Credits and x402 prices

Requests sent **without** an API key to a v2 endpoint get an HTTP 402 [x402](/ai-agents/x402) challenge instead of using credits. On 2026-10-23, every 402 we captured priced the request at exactly **credits × $0.002**, expressed in `accepts[].amount` as USDC base units (6 decimals):

| Request (no key) | `accepts[].amount` | = USD | Credits on this page |
| - | -: | -: | -: |
| `GET /v2/networks` | 2000 | $0.002 | 1 |
| `GET /v2/detailed-vaults/base/{vaultId}/apy` | 2000 | $0.002 | 1 |
| `GET /v2/transactions/suffix/{userAddress}/{vaultId}` | 2000 | $0.002 | 1 |
| `GET /v2/portfolio/best-vault/{userAddress}` | 4000 | $0.004 | 2 |
| `GET /v2/detailed-vaults/base/{vaultId}` | 6000 | $0.006 | 3 |
| `GET /v2/benchmarks/base?code=usd` | 6000 | $0.006 | 3 |
| `GET /v2/transactions/rewards/context/{userAddress}` | 6000 | $0.006 | 3 |
| `GET /v2/detailed-vaults?perPage=1` | 8000 | $0.008 | 1 + 1 × 3 = 4 |
| `GET /v2/detailed-vaults?perPage=5` | 32000 | $0.032 | 1 + 5 × 3 = 16 |
| `GET /v2/portfolio/positions/{userAddress}` | 10000 | $0.010 | 5 |
| `GET /v2/transactions/deposit/...` | 10000 | $0.010 | 5 |
| `GET /v2/historical/base/{vaultId}/apy?perPage=1` | 4000 (scheme `upto`, a maximum) | $0.004 | 1 + 1 × 1 = 2 |
| `GET /v2/historical/base/{vaultId}/apy?perPage=10` | 22000 (scheme `upto`, a maximum) | $0.022 | 1 + 10 × 1 = 11 |

The x402 price is defined as the credit cost × $0.002 (2000 USDC base units per credit), with list and historical endpoints priced for the full `perPage` you request. Historical endpoints use the `upto` scheme and settle only for the data points actually returned; other endpoints, including `/v2/detailed-vaults`, charge the quoted amount even if fewer items come back. x402 is available on `/v2/*` data endpoints and `POST /beta/advanced-analytics`; NRT, other beta and alpha endpoints need an API key. Always pay the amount in `accepts[].amount` rather than hard-coding it.

x402 payments don't draw on account credits. Keyless (x402) traffic is limited to 10 requests per minute per IP.

## When credits run out

Before each priced request the API checks the key's credit balance. When it has reached zero, the request returns HTTP **403** with `{"error":"Forbidden","message":"This API key has exhausted its available credits. To resume service, please visit https://portal.vaults.fyi/signup to top-up your credits"}`. Don't retry a 403; top up or upgrade. Free endpoints (health, alpha) are not affected. See [Errors](/api-reference/errors#403-credits-exhausted).

Pay-as-you-go keys have no spending cap: usage is billed per credit with no upper limit, so set your own budget alerts or call limits if you need one.
