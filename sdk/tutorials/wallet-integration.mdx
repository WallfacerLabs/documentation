This tutorial builds the core yield flow of a wallet with the vaults.fyi SDK: find the user's idle tokens, suggest vaults for them, build a deposit the user signs, and show the resulting position. Use it when you integrate Earn into a wallet or consumer app. The REST equivalents of each step are in the [recipes](/recipes/overview).

Tested on 2026-10-23 with **`@vaultsfyi/sdk` 2.3.14** and **`vaultsfyi` 1.3.0** against the live API, read-only, for the public address `0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045`. The SDKs send the key as `x-api-key`. Balances are base-unit strings; APY values are decimal fractions. **The signing step was not executed** (it runs only with `SEND=1`).

## Prerequisites

- An API key in `VAULTSFYI_API_KEY` ([SDK quickstart](/sdk/quickstart) covers install and setup).
- TypeScript: Node.js 18+, `@vaultsfyi/sdk@2.3.14`, `viem` 2.x, an ESM project. Python: Python 3.8+, `vaultsfyi==1.3.0`.

## Credit cost of one full flow

| Step | SDK method | REST endpoint | Credits |
| - | - | - | - |
| 1. Idle assets | `getIdleAssets` / `get_idle_assets` | `GET /v2/portfolio/idle-assets/{userAddress}` | 5 |
| 2. Deposit options | `getDepositOptions` / `get_deposit_options` | `GET /v2/portfolio/best-deposit-options/{userAddress}` | 1 + 2 per vault (this run: 9 vaults = 19) |
| 3. Context | `getTransactionsContext` / `get_transactions_context` | `GET /v2/transactions/context/{userAddress}/{network}/{vaultId}` | 3 |
| 4. Payload | `getActions` / `get_actions` | `GET /v2/transactions/{action}/{userAddress}/{network}/{vaultId}` | 5 |
| 5. Position | `getPositions` / `get_positions` | `GET /v2/portfolio/positions/{userAddress}` | 5 |
| **Total** | | | **37** |

([credits](/plans/credits)). Cache steps 1, 2 and 5 per session; always run 3 and 4 fresh right before signing.

## The full script (TypeScript)

```typescript
// Wallet integration with @vaultsfyi/sdk 2.3.14: idle assets -> deposit options -> context ->
// payload -> verify -> sign (only when SEND=1) -> position. Node >= 18, ESM.
import { VaultsSdk } from '@vaultsfyi/sdk';
import { createPublicClient, createWalletClient, getAddress, http, type Hex } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { base } from 'viem/chains';

const sdk = new VaultsSdk({ apiKey: process.env.VAULTSFYI_API_KEY! }); // sent as x-api-key
const USER = '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045'; // the connected wallet
const NETWORK = 'base';

// Base-unit string -> human string, exact (no float rounding).
const human = (raw: string, decimals: number, dp = 4) => {
  const s = BigInt(raw).toString().padStart(decimals + 1, '0');
  return decimals ? `${s.slice(0, -decimals)}.${s.slice(-decimals).slice(0, dp)}` : s;
};

// 1) Idle assets: tokens in the wallet that are not deposited anywhere (5 credits).
const idle = await sdk.getIdleAssets({ path: { userAddress: USER }, query: { allowedNetworks: [NETWORK] } });
for (const a of idle.data.slice(0, 3)) {
  console.log(`idle ${a.symbol}: ${human(a.balanceNative, a.decimals)} (~$${Number(a.balanceUsd ?? 0).toFixed(2)})`);
}

// 2) Deposit options for what the wallet holds (1 credit + 2 per vault returned).
const options = await sdk.getDepositOptions({
  path: { userAddress: USER },
  query: { allowedNetworks: [NETWORK], onlyTransactional: true, maxVaultsPerAsset: 2 },
});
for (const b of options.userBalances.slice(0, 2)) {
  for (const v of b.depositOptions) {
    console.log(`option ${b.asset?.symbol} -> ${v.name}: ${(v.apy.total * 100).toFixed(2)} % (vaultId ${v.vaultId})`);
  }
}

// 3) The user picks a vault in your UI. Read its transaction context first (3 credits).
const VAULT_ID = '0xbeeff2490FEffa212faC2f6553682C219E6a8845'; // Steakhouse High Yield USDC
const ctx = await sdk.getTransactionsContext({ path: { userAddress: USER, network: NETWORK, vaultId: VAULT_ID } });
if (ctx.currentDepositStep !== 'deposit') throw new Error(`next step is ${ctx.currentDepositStep}`);
const amount = 10n ** BigInt(ctx.asset.decimals); // 1 USDC in base units = 1000000
if (amount > BigInt(ctx.asset.balanceNative)) throw new Error('insufficient balance'); // the API does not check

// 4) Build the unsigned payload (5 credits). amount is a base-unit integer string.
const tx = await sdk.getActions({
  path: { action: 'deposit', userAddress: USER, network: NETWORK, vaultId: VAULT_ID },
  query: { assetAddress: ctx.asset.address, amount: amount.toString() },
});

// 5) Verify every action before showing it to the user.
const allowedTargets = [getAddress(ctx.asset.address), getAddress(VAULT_ID)];
for (const a of tx.actions) {
  if (a.tx.chainId !== base.id) throw new Error(`wrong chain ${a.tx.chainId}`);
  if (!allowedTargets.includes(getAddress(a.tx.to))) throw new Error(`unexpected target ${a.tx.to}`);
  console.log(`action: ${a.name} -> ${a.tx.to}`);
}

// 6) Sign and send IN ORDER, waiting for each receipt. Never runs unless SEND=1.
if (process.env.SEND === '1') {
  const account = privateKeyToAccount(process.env.PRIVATE_KEY as Hex); // the user's key, held by the wallet
  const wallet = createWalletClient({ account, chain: base, transport: http() });
  const pub = createPublicClient({ chain: base, transport: http() });
  for (const a of tx.actions.slice(tx.currentActionIndex)) {
    const hash = await wallet.sendTransaction({ to: a.tx.to as Hex, ...(a.tx.data !== undefined ? { data: a.tx.data as Hex } : {}), value: BigInt(a.tx.value ?? 0) });
    const receipt = await pub.waitForTransactionReceipt({ hash });
    if (receipt.status !== 'success') throw new Error(`${a.name} reverted: ${hash}`);
  }
} else {
  console.log('dry run: not signing (set SEND=1 in a real wallet)');
}

// 7) Track the position (5 credits). Position size = asset.positionValueInAsset, NOT asset.balanceNative.
const positions = await sdk.getPositions({ path: { userAddress: USER }, query: { allowedNetworks: [NETWORK] } });
for (const p of positions.data) {
  console.log(`position ${p.name}: ${human(p.asset.positionValueInAsset ?? '0', p.asset.decimals)} ${p.asset.symbol}`);
}
```

## The same flow in Python (build and verify only)

The Python SDK has no signer; hand `actions[currentActionIndex:]` to your wallet library and send them in order.

```python
"""Wallet integration with the vaultsfyi Python SDK 1.3.0: idle assets -> deposit options -> context ->
payload -> verify. Signing is left to your wallet library; this script never signs."""
import os
from decimal import Decimal

from vaultsfyi import VaultsSdk

client = VaultsSdk(api_key=os.environ["VAULTSFYI_API_KEY"])  # sent as x-api-key
USER = "0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045"  # the connected wallet
NETWORK, CHAIN_ID = "base", 8453


def human(raw, decimals):
    """Base-unit integer string -> Decimal tokens."""
    return Decimal(raw) / (Decimal(10) ** decimals)


# 1) Idle assets (5 credits). balanceNative is a base-unit string.
idle = client.get_idle_assets(USER, allowed_networks=[NETWORK])
for a in idle["data"][:3]:
    print(f'idle {a["symbol"]}: {human(a["balanceNative"], a["decimals"]):.4f} (~${float(a.get("balanceUsd") or 0):.2f})')

# 2) Deposit options (1 credit + 2 per vault returned).
options = client.get_deposit_options(USER, allowed_networks=[NETWORK], only_transactional=True, max_vaults_per_asset=2)
for b in options["userBalances"][:2]:
    for v in b["depositOptions"]:
        print(f'option {b["asset"]["symbol"]} -> {v["name"]}: {v["apy"]["total"] * 100:.2f} % (vaultId {v["vaultId"]})')

# 3) Context for the vault the user picked (3 credits). The SDK calls the vaultId argument vault_address.
VAULT_ID = "0xbeeff2490FEffa212faC2f6553682C219E6a8845"  # Steakhouse High Yield USDC
ctx = client.get_transactions_context(USER, NETWORK, VAULT_ID)
assert ctx["currentDepositStep"] == "deposit", ctx["currentDepositStep"]
amount = 10 ** ctx["asset"]["decimals"]  # 1 USDC = 1000000 base units
assert amount <= int(ctx["asset"]["balanceNative"]), "insufficient balance"  # the API does not check

# 4) Unsigned payload (5 credits).
tx = client.get_actions("deposit", USER, NETWORK, VAULT_ID, asset_address=ctx["asset"]["address"], amount=str(amount))

# 5) Verify chain and targets, then hand actions[currentActionIndex:] to the wallet IN ORDER.
allowed = {ctx["asset"]["address"].lower(), VAULT_ID.lower()}
for a in tx["actions"][tx["currentActionIndex"]:]:
    assert a["tx"]["chainId"] == CHAIN_ID and a["tx"]["to"].lower() in allowed, a
    print(f'action: {a["name"]} -> {a["tx"]["to"]}')

# 6) Position (5 credits): size is asset.positionValueInAsset; asset.balanceNative is the idle wallet balance.
for p in client.get_positions(USER, allowed_networks=[NETWORK])["data"]:
    print(f'position {p["name"]}: {human(p["asset"]["positionValueInAsset"], p["asset"]["decimals"]):.4f} {p["asset"]["symbol"]}')
```

## Step notes

### 1. Idle assets

Returns `{ data: [{ symbol, decimals, balanceNative, balanceUsd?, network, … }], errors }`. Defaults to the four networks base, mainnet, arbitrum and optimism; pass `allowedNetworks` for others. Hide dust balances before suggesting deposits: gas can exceed the yield.

### 2. Deposit options

Returns `{ requestedAddress, userBalances: [{ asset, depositOptions: [{ vaultId, name, network, apy: { base, reward, total }, tvl, projectedUsdAnnualEarnings }] }] }`. Defaults: `minTvl=100000`, `onlyAppFeatured=true`, `allowVaultsWithWarnings=false`, `maxVaultsPerAsset=3`, 7-day APY. Pass `onlyTransactional: true` so every option can be deposited through the Transactions API. Very high APYs (69.75 % above) are real values; apply your own TVL and score policy.

### 3. Context

`currentDepositStep` tells you what to build next (`deposit` here). `asset.address` and `asset.decimals` give you the `assetAddress` and the base-unit scale. The API does **not** check the balance or limits for you; compare `amount` with `asset.balanceNative` yourself.

### 4. Payload and verification

`getActions` returns `{ currentActionIndex, actions: [{ name, tx: { to, chainId, data, value? } }] }`, here an `approve` on USDC and a `deposit` on the vault. Verify `chainId`, `to`, `value` and, ideally, the decoded arguments ([build a deposit](/recipes/deposit-transaction) decodes them with viem). Show `actions[].name` and the amount to the user before signing.

### 5. Sign and send in order

Send `actions[currentActionIndex:]` one at a time and wait for each receipt; the deposit fails if the approval is not mined. Never let an API, SDK or agent hold the user's private key. For smart-contract wallets you can batch the calls yourself; see [transaction flows](/concepts/transaction-flows#eoa-and-smart-contract-wallets).

### 6. Position

The position size is `asset.positionValueInAsset` (asset base units). `asset.balanceNative` on a position is the wallet's **idle** balance of that asset; don't add it. Returns and events (`getUserVaultTotalReturns`, `getUserVaultEvents`) need `userEventsIndexed: true` on the vault.

## Pitfalls fixed from earlier versions of this tutorial

- `import pkg from '@vaultsfyi/sdk'` → `import { VaultsSdk } from '@vaultsfyi/sdk'`.
- `path: { …, vaultAddress }` → `path: { …, vaultId }` (TypeScript).
- `cd python_examples/` → the repository directory is `python-examples`.
- "Context reports deposit limits and the API rejects deposits over them" → the API does no balance or limit check; check yourself.
- The flow stopped before signing → step 5 shows ordered signing with receipts.
