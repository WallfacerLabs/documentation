# SDK quickstart: TypeScript (@vaultsfyi/sdk) and Python (vaultsfyi)
Source: https://docs.vaults.fyi/sdk/quickstart

> Install @vaultsfyi/sdk 2.3.14 or vaultsfyi 1.3.0, set VAULTSFYI_API_KEY, and run a tested first script that fetches deposit options for a wallet and one vault's APY; includes response shape, defaults, credit cost and SDK-specific pitfalls.

This page gets you from nothing to a working vaults.fyi SDK call in TypeScript or Python. It installs the published packages, sets the API key, runs one script that fetches personalized deposit options for a wallet and one vault's APY, and lists the SDK quirks that break code copied from older docs. Use it before the [SDK reference](/sdk/reference).

Tested on 2026-10-23 with **`@vaultsfyi/sdk` 2.3.14** (Node.js 18+, ESM) and **`vaultsfyi` 1.3.0** (Python 3.8+; tested on 3.9), from a clean install in an empty directory. Both SDKs call the REST API at `https://api.vaults.fyi` and send your key in the `x-api-key` header. Outputs below are real.

## 1. Install

TypeScript (the script runs with `tsx`; any ESM TypeScript runner works):

```bash
npm install @vaultsfyi/sdk@2.3.14 tsx
```

Python:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install vaultsfyi==1.3.0
```

## 2. Set your API key

Get a key at [portal.vaults.fyi](https://portal.vaults.fyi/signup) (pay-as-you-go is $0.002 per credit). Keep it in the environment, never in code:

```bash
export VAULTSFYI_API_KEY="<your API key from portal.vaults.fyi>"
```

## 3. First script

TypeScript, saved as `quickstart.ts` (the project's `package.json` needs `"type": "module"`):

```typescript
// SDK quickstart (TypeScript, @vaultsfyi/sdk 2.3.14). Node >= 18, ESM ("type": "module").
import { VaultsSdk } from '@vaultsfyi/sdk';

const sdk = new VaultsSdk({ apiKey: process.env.VAULTSFYI_API_KEY! }); // sent as x-api-key

// First call: personalized deposit options for a wallet (GET /v2/portfolio/best-deposit-options/{userAddress}).
const options = await sdk.getDepositOptions({
  path: { userAddress: '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045' },
  query: { allowedAssets: ['USDC'], onlyTransactional: true, maxVaultsPerAsset: 2 },
});
for (const b of options.userBalances) {
  if (!b.asset) continue; // typed optional in the SDK; always present in practice
  console.log(b.asset.symbol, 'balance (base units):', b.asset.balanceNative, 'decimals:', b.asset.decimals);
  for (const v of b.depositOptions) {
    console.log(`  ${v.network.name} ${v.name}: ${(v.apy.total * 100).toFixed(2)} %  vaultId ${v.vaultId}`);
  }
}

// One vault (path key is vaultId, not vaultAddress).
const vault = await sdk.getVault({ path: { network: 'base', vaultId: '0xbeeff2490FEffa212faC2f6553682C219E6a8845' } });
console.log(vault.name, '7d APY', `${(vault.apy['7day'].total * 100).toFixed(2)} %`);
```

Python, saved as `quickstart.py`:

```python
"""SDK quickstart (Python, vaultsfyi 1.3.0). Python >= 3.8."""
import os

from vaultsfyi import VaultsSdk

client = VaultsSdk(api_key=os.environ["VAULTSFYI_API_KEY"])  # sent as x-api-key

options = client.get_deposit_options(
    "0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045",
    allowed_assets=["USDC"],
    only_transactional=True,
    max_vaults_per_asset=2,
)
for b in options["userBalances"]:
    print(b["asset"]["symbol"], "balance (base units):", b["asset"]["balanceNative"], "decimals:", b["asset"]["decimals"])
    for v in b["depositOptions"]:
        print(f'  {v["network"]["name"]} {v["name"]}: {v["apy"]["total"] * 100:.2f} %  vaultId {v["vaultId"]}')

# One vault. The Python SDK names this argument vault_address, but it is the REST vaultId.
vault = client.get_vault("base", "0xbeeff2490FEffa212faC2f6553682C219E6a8845")
print(vault["name"], "7d APY", f'{vault["apy"]["7day"]["total"] * 100:.2f} %')
```

## Things that differ from older SDK docs

- **Import (TypeScript):** `import { VaultsSdk } from '@vaultsfyi/sdk'`. The package exports only `VaultsSdk` and `SUPPORTED_NETWORKS`; it has no default export.
- **Vault path key (TypeScript):** `path: { network, vaultId }`. With `vaultAddress` the SDK requests `/undefined` and fails.
- **Vault argument (Python):** positional or `vault_address=`, but pass the REST **`vaultId`** (usually the address; not always).
- **Responses are envelopes, not arrays:** list methods return `{ itemsOnPage, nextPage?, data }`; `nextPage` is absent on the last page.
- **Units are unchanged by the SDK:** APY is a decimal fraction (`0.0315` = 3.15 %), amounts are base-unit strings, timestamps are Unix seconds.
- **Arrays** (`allowedNetworks: ['base', 'arbitrum']`) are sent as repeated query keys, which is what the API expects.
- **Errors:** the TypeScript SDK throws an `Error` with only a `message` (no status code) and does not retry; the Python SDK raises typed exceptions and retries 429/5xx. See [SDK reference: errors](/sdk/reference#errors-and-retries).
- **Keyless x402 mode (TypeScript):** `new VaultsSdk({ client: signer })` exists; 2.3.14 uses an x402 v1 client, while the API uses x402 v2. Use an API key, or an x402 v2 client as shown on [x402](/ai-agents/x402).

# SDK reference: every @vaultsfyi/sdk and vaultsfyi method with its REST endpoint
Source: https://docs.vaults.fyi/sdk/reference

> Every method of @vaultsfyi/sdk 2.3.14 (TypeScript) and vaultsfyi 1.3.0 (Python), mapped to its v2 REST endpoint, parameters, credit cost and live return shape, plus tested examples, error classes and retry behaviour.

This page lists every public method of the two official vaults.fyi SDKs, the REST endpoint each one wraps, its parameters, its credit cost and the shape it returned when called live. Use it to pick a method, to translate between SDK and REST, and to handle SDK errors correctly. For a first working script, see the [SDK quickstart](/sdk/quickstart).

Generated from the published packages **`@vaultsfyi/sdk` 2.3.14** and **`vaultsfyi` 1.3.0**. Every TypeScript method (35) and every Python method (29, including one deprecated alias) was called once against the live API on 2026-10-23, read-only. Both SDKs send the key in the `x-api-key` header to `https://api.vaults.fyi`, and return the API's JSON unchanged: APY values are decimal fractions, amounts are base-unit strings, timestamps are Unix seconds.

## Constructors

| | TypeScript | Python |
| - | - | - |
| With an API key | `new VaultsSdk({ apiKey })` | `VaultsSdk(api_key, api_base_url="https://api.vaults.fyi", timeout=30, max_retries=3)` |
| Keyless (x402) | `new VaultsSdk({ client: signer })`: uses `x402-fetch` 0.7.0 (x402 v1); the API uses x402 v2. See [x402](/ai-agents/x402). | not supported |
| Timeout / retries | none (plain `fetch`, no retries) | `timeout` seconds; `max_retries` retries on 429, 500, 502, 503, 504 for GET, backoff factor 1 |
| Other exports | `SUPPORTED_NETWORKS` (22 network names) | exceptions in `vaultsfyi.exceptions` |

TypeScript methods take one object `{ path?, query? }` whose keys are the REST names (`vaultId`, `userAddress`, `allowedNetworks`). Python methods take path parameters positionally and query parameters as snake_case keywords (`allowed_networks`), converted to the REST names; extra `**kwargs` are passed through as REST query parameters unchanged. Lists are sent as repeated keys in both SDKs.

Setup used by every example below:

```typescript
import { VaultsSdk, SUPPORTED_NETWORKS } from '@vaultsfyi/sdk';

const sdk = new VaultsSdk({ apiKey: process.env.VAULTSFYI_API_KEY! });
const USER = '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045'; // any 0x wallet address
const NETWORK = 'base';
const VAULT_ID = '0xbeeff2490FEffa212faC2f6553682C219E6a8845'; // Steakhouse High Yield USDC (Base)
const USDC_BASE = '0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913';
const now = Math.floor(Date.now() / 1000 / 86400) * 86400; // Unix SECONDS, midnight UTC
```

## Errors and retries

The two SDKs behave differently. Verified with a local stub server returning each status (no API calls) and with a live 400:

| HTTP status | Python `vaultsfyi` 1.3.0 (`max_retries=3`) | TypeScript `@vaultsfyi/sdk` 2.3.14 |
| - | - | - |
| 400 (validation) | `HttpResponseError`, `status_code=400`, 1 request | `Error` subclass (`HttpResponseError`, not exported), only `message`, 1 request |
| 401 (invalid key) | `AuthenticationError`, 1 request | same plain error, no status |
| 402 (no key) | `HttpResponseError`, `status_code=402`, 1 request | same plain error, no status |
| 403 (credits exhausted) | `ForbiddenError`, 1 request | same plain error, no status |
| 404 | `HttpResponseError`, `status_code=404` | same plain error, no status |
| 429, 500, 503 | `NetworkError` after 4 requests (about 6 s) | plain error after 1 request: **no retries** |

The live 400 for `sortBy: 'apy'`: the message is the API's JSON-encoded issue list.

TypeScript (the error class is not exported, so catch `Error` and read `message`):

```typescript
try {
  await sdk.getAllVaults({ query: { sortBy: 'apy' as never, perPage: 1 } });
} catch (err) {
  // HttpResponseError is NOT exported and has no status code: only `message` is available.
  console.log('SDK error:', (err as Error).constructor.name, (err as Error).message.slice(0, 80).replace(/\s+/g, ' '));
}
```

```text
SDK error: HttpResponseError [ { "received": "apy", "code": "invalid_enum_value", "options": [ 
```

Python:

```python
try:
    client.get_detailed_vaults(sort_by="apy", per_page=1)  # invalid enum -> HTTP 400
except AuthenticationError as e:    # 401: key sent but invalid
    print("auth", e)
except ForbiddenError as e:         # 403: credits exhausted
    print("forbidden", e)
except RateLimitError as e:         # 429 per the code, but in 1.3.0 a 429 surfaces as NetworkError (see below)
    print("rate limited", e)
except HttpResponseError as e:      # any other non-2xx, incl. 400 and 402 (no key)
    print("HTTP", e.status_code, str(e)[:60].replace("\n", " "))
except NetworkError as e:           # connection errors AND 429/500/502/503/504 after the built-in retries
    print("network", e)
```

```text
HTTP 400 [   {     "received": "apy",     "code": "invalid_enum_value
```

What to do:

- **TypeScript:** add your own retry with backoff for transient failures, and don't retry on messages that describe validation or auth problems. If you need the status code, call the REST API directly (see [handle errors and retries](/recipes/handle-errors-and-retries)).
- **Python:** catch `NetworkError` to detect exhausted 429/5xx retries. Set `max_retries=0` if you run your own retry loop, to avoid multiplying requests.
- **Both:** a 200 can still carry soft errors in `errors.unsupported*`; check them after list calls.

Exception classes exported by `vaultsfyi` 1.3.0: `VaultsFyiError` (base), `HttpResponseError` (`status_code`, `response_data`), `AuthenticationError`, `ForbiddenError`, `RateLimitError`, `NetworkError`.

## SDK coverage and error handling (2.3.14 / 1.3.0)

- Python: no methods for `/v2/protocols`, `/v2/transactions/suffix/...` or `/v2/nrt/...`.
- Python names the vault argument `vault_address`; REST and TypeScript use `vaultId`.
- TypeScript errors carry no status code; no retries.
- TypeScript x402 mode uses an x402 v1 client; the API uses x402 v2.
- Neither SDK covers Beta (Solana, borrow, Pendle) or Alpha endpoints.

Report SDK issues to the maintainers; see the package pages on npm and PyPI.

# Tutorial: add yield to a wallet with the vaults.fyi SDK
Source: https://docs.vaults.fyi/sdk/tutorials/wallet-integration

> Tested SDK walkthrough for wallets: detect idle assets, show deposit options, read the transaction context, build and verify an unsigned deposit, sign it in order with viem (shown, not executed), then track the position; with credit cost per step.

This tutorial builds the core yield flow of a wallet with the vaults.fyi SDK: find the user's idle tokens, suggest vaults for them, build a deposit the user signs, and show the resulting position. Use it when you integrate Earn into a wallet or consumer app. The REST equivalents of each step are in the [recipes](/recipes/overview).

Tested on 2026-10-23 with **`@vaultsfyi/sdk` 2.3.14** and **`vaultsfyi` 1.3.0** against the live API, read-only, for the public address `0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045`. The SDKs send the key as `x-api-key`. Balances are base-unit strings; APY values are decimal fractions. **The signing step was not executed** (it runs only with `SEND=1`).

## Prerequisites

- An API key in `VAULTSFYI_API_KEY` ([SDK quickstart](/sdk/quickstart) covers install and setup).
- TypeScript: Node.js 18+, `@vaultsfyi/sdk@2.3.14`, `viem` 2.x, an ESM project. Python: Python 3.8+, `vaultsfyi==1.3.0`.

## Credit cost of one full flow

| Step | SDK method | REST endpoint | Credits |
| - | - | - | - |
| 1. Idle assets | `getIdleAssets` / `get_idle_assets` | `GET /v2/portfolio/idle-assets/{userAddress}` | 5 |
| 2. Deposit options | `getDepositOptions` / `get_deposit_options` | `GET /v2/portfolio/best-deposit-options/{userAddress}` | 1 + 2 per vault (this run: 9 vaults = 19) |
| 3. Context | `getTransactionsContext` / `get_transactions_context` | `GET /v2/transactions/context/{userAddress}/{network}/{vaultId}` | 3 |
| 4. Payload | `getActions` / `get_actions` | `GET /v2/transactions/{action}/{userAddress}/{network}/{vaultId}` | 5 |
| 5. Position | `getPositions` / `get_positions` | `GET /v2/portfolio/positions/{userAddress}` | 5 |
| **Total** | | | **37** |

([credits](/plans/credits)). Cache steps 1, 2 and 5 per session; always run 3 and 4 fresh right before signing.

## The full script (TypeScript)

```typescript
// Wallet integration with @vaultsfyi/sdk 2.3.14: idle assets -> deposit options -> context ->
// payload -> verify -> sign (only when SEND=1) -> position. Node >= 18, ESM.
import { VaultsSdk } from '@vaultsfyi/sdk';
import { createPublicClient, createWalletClient, getAddress, http, type Hex } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { base } from 'viem/chains';

const sdk = new VaultsSdk({ apiKey: process.env.VAULTSFYI_API_KEY! }); // sent as x-api-key
const USER = '0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045'; // the connected wallet
const NETWORK = 'base';

// Base-unit string -> human string, exact (no float rounding).
const human = (raw: string, decimals: number, dp = 4) => {
  const s = BigInt(raw).toString().padStart(decimals + 1, '0');
  return decimals ? `${s.slice(0, -decimals)}.${s.slice(-decimals).slice(0, dp)}` : s;
};

// 1) Idle assets: tokens in the wallet that are not deposited anywhere (5 credits).
const idle = await sdk.getIdleAssets({ path: { userAddress: USER }, query: { allowedNetworks: [NETWORK] } });
for (const a of idle.data.slice(0, 3)) {
  console.log(`idle ${a.symbol}: ${human(a.balanceNative, a.decimals)} (~$${Number(a.balanceUsd ?? 0).toFixed(2)})`);
}

// 2) Deposit options for what the wallet holds (1 credit + 2 per vault returned).
const options = await sdk.getDepositOptions({
  path: { userAddress: USER },
  query: { allowedNetworks: [NETWORK], onlyTransactional: true, maxVaultsPerAsset: 2 },
});
for (const b of options.userBalances.slice(0, 2)) {
  for (const v of b.depositOptions) {
    console.log(`option ${b.asset?.symbol} -> ${v.name}: ${(v.apy.total * 100).toFixed(2)} % (vaultId ${v.vaultId})`);
  }
}

// 3) The user picks a vault in your UI. Read its transaction context first (3 credits).
const VAULT_ID = '0xbeeff2490FEffa212faC2f6553682C219E6a8845'; // Steakhouse High Yield USDC
const ctx = await sdk.getTransactionsContext({ path: { userAddress: USER, network: NETWORK, vaultId: VAULT_ID } });
if (ctx.currentDepositStep !== 'deposit') throw new Error(`next step is ${ctx.currentDepositStep}`);
const amount = 10n ** BigInt(ctx.asset.decimals); // 1 USDC in base units = 1000000
if (amount > BigInt(ctx.asset.balanceNative)) throw new Error('insufficient balance'); // the API does not check

// 4) Build the unsigned payload (5 credits). amount is a base-unit integer string.
const tx = await sdk.getActions({
  path: { action: 'deposit', userAddress: USER, network: NETWORK, vaultId: VAULT_ID },
  query: { assetAddress: ctx.asset.address, amount: amount.toString() },
});

// 5) Verify every action before showing it to the user.
const allowedTargets = [getAddress(ctx.asset.address), getAddress(VAULT_ID)];
for (const a of tx.actions) {
  if (a.tx.chainId !== base.id) throw new Error(`wrong chain ${a.tx.chainId}`);
  if (!allowedTargets.includes(getAddress(a.tx.to))) throw new Error(`unexpected target ${a.tx.to}`);
  console.log(`action: ${a.name} -> ${a.tx.to}`);
}

// 6) Sign and send IN ORDER, waiting for each receipt. Never runs unless SEND=1.
if (process.env.SEND === '1') {
  const account = privateKeyToAccount(process.env.PRIVATE_KEY as Hex); // the user's key, held by the wallet
  const wallet = createWalletClient({ account, chain: base, transport: http() });
  const pub = createPublicClient({ chain: base, transport: http() });
  for (const a of tx.actions.slice(tx.currentActionIndex)) {
    const hash = await wallet.sendTransaction({ to: a.tx.to as Hex, ...(a.tx.data !== undefined ? { data: a.tx.data as Hex } : {}), value: BigInt(a.tx.value ?? 0) });
    const receipt = await pub.waitForTransactionReceipt({ hash });
    if (receipt.status !== 'success') throw new Error(`${a.name} reverted: ${hash}`);
  }
} else {
  console.log('dry run: not signing (set SEND=1 in a real wallet)');
}

// 7) Track the position (5 credits). Position size = asset.positionValueInAsset, NOT asset.balanceNative.
```

## The same flow in Python (build and verify only)

The Python SDK has no signer; hand `actions[currentActionIndex:]` to your wallet library and send them in order.

```python
"""Wallet integration with the vaultsfyi Python SDK 1.3.0: idle assets -> deposit options -> context ->
payload -> verify. Signing is left to your wallet library; this script never signs."""
import os
from decimal import Decimal

from vaultsfyi import VaultsSdk

client = VaultsSdk(api_key=os.environ["VAULTSFYI_API_KEY"])  # sent as x-api-key
USER = "0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045"  # the connected wallet
NETWORK, CHAIN_ID = "base", 8453


def human(raw, decimals):
    """Base-unit integer string -> Decimal tokens."""
    return Decimal(raw) / (Decimal(10) ** decimals)


# 1) Idle assets (5 credits). balanceNative is a base-unit string.
idle = client.get_idle_assets(USER, allowed_networks=[NETWORK])
for a in idle["data"][:3]:
    print(f'idle {a["symbol"]}: {human(a["balanceNative"], a["decimals"]):.4f} (~${float(a.get("balanceUsd") or 0):.2f})')

# 2) Deposit options (1 credit + 2 per vault returned).
options = client.get_deposit_options(USER, allowed_networks=[NETWORK], only_transactional=True, max_vaults_per_asset=2)
for b in options["userBalances"][:2]:
    for v in b["depositOptions"]:
        print(f'option {b["asset"]["symbol"]} -> {v["name"]}: {v["apy"]["total"] * 100:.2f} % (vaultId {v["vaultId"]})')

# 3) Context for the vault the user picked (3 credits). The SDK calls the vaultId argument vault_address.
VAULT_ID = "0xbeeff2490FEffa212faC2f6553682C219E6a8845"  # Steakhouse High Yield USDC
ctx = client.get_transactions_context(USER, NETWORK, VAULT_ID)
assert ctx["currentDepositStep"] == "deposit", ctx["currentDepositStep"]
amount = 10 ** ctx["asset"]["decimals"]  # 1 USDC = 1000000 base units
assert amount <= int(ctx["asset"]["balanceNative"]), "insufficient balance"  # the API does not check

# 4) Unsigned payload (5 credits).
tx = client.get_actions("deposit", USER, NETWORK, VAULT_ID, asset_address=ctx["asset"]["address"], amount=str(amount))

# 5) Verify chain and targets, then hand actions[currentActionIndex:] to the wallet IN ORDER.
allowed = {ctx["asset"]["address"].lower(), VAULT_ID.lower()}
for a in tx["actions"][tx["currentActionIndex"]:]:
    assert a["tx"]["chainId"] == CHAIN_ID and a["tx"]["to"].lower() in allowed, a
    print(f'action: {a["name"]} -> {a["tx"]["to"]}')

# 6) Position (5 credits): size is asset.positionValueInAsset; asset.balanceNative is the idle wallet balance.
for p in client.get_positions(USER, allowed_networks=[NETWORK])["data"]:
    print(f'position {p["name"]}: {human(p["asset"]["positionValueInAsset"], p["asset"]["decimals"]):.4f} {p["asset"]["symbol"]}')
```

## Step notes

### 1. Idle assets

Returns `{ data: [{ symbol, decimals, balanceNative, balanceUsd?, network, … }], errors }`. Defaults to the four networks base, mainnet, arbitrum and optimism; pass `allowedNetworks` for others. Hide dust balances before suggesting deposits: gas can exceed the yield.

### 2. Deposit options

Returns `{ requestedAddress, userBalances: [{ asset, depositOptions: [{ vaultId, name, network, apy: { base, reward, total }, tvl, projectedUsdAnnualEarnings }] }] }`. Defaults: `minTvl=100000`, `onlyAppFeatured=true`, `allowVaultsWithWarnings=false`, `maxVaultsPerAsset=3`, 7-day APY. Pass `onlyTransactional: true` so every option can be deposited through the Transactions API. Very high APYs (69.75 % above) are real values; apply your own TVL and score policy.

### 3. Context

`currentDepositStep` tells you what to build next (`deposit` here). `asset.address` and `asset.decimals` give you the `assetAddress` and the base-unit scale. The API does **not** check the balance or limits for you; compare `amount` with `asset.balanceNative` yourself.

### 4. Payload and verification

`getActions` returns `{ currentActionIndex, actions: [{ name, tx: { to, chainId, data, value? } }] }`, here an `approve` on USDC and a `deposit` on the vault. Verify `chainId`, `to`, `value` and, ideally, the decoded arguments ([build a deposit](/recipes/deposit-transaction) decodes them with viem). Show `actions[].name` and the amount to the user before signing.

### 5. Sign and send in order

Send `actions[currentActionIndex:]` one at a time and wait for each receipt; the deposit fails if the approval is not mined. Never let an API, SDK or agent hold the user's private key. For smart-contract wallets you can batch the calls yourself; see [transaction flows](/concepts/transaction-flows#eoa-and-smart-contract-wallets).

### 6. Position

The position size is `asset.positionValueInAsset` (asset base units). `asset.balanceNative` on a position is the wallet's **idle** balance of that asset; don't add it. Returns and events (`getUserVaultTotalReturns`, `getUserVaultEvents`) need `userEventsIndexed: true` on the vault.

## Pitfalls fixed from earlier versions of this tutorial

- `import pkg from '@vaultsfyi/sdk'` → `import { VaultsSdk } from '@vaultsfyi/sdk'`.
- `path: { …, vaultAddress }` → `path: { …, vaultId }` (TypeScript).
- `cd python_examples/` → the repository directory is `python-examples`.
- "Context reports deposit limits and the API rejects deposits over them" → the API does no balance or limit check; check yourself.
- The flow stopped before signing → step 5 shows ordered signing with receipts.

# Tutorial: yield analytics with the vaults.fyi SDK
Source: https://docs.vaults.fyi/sdk/tutorials/data-analytics

> Tested SDK walkthrough for analysts: page through /v2/detailed-vaults with the 4-network and minTvl defaults overridden, pull 90 days of daily APY, compare a vault with the USD benchmark, and budget credits, in TypeScript and Python.

This tutorial builds a small analytics pipeline with the vaults.fyi SDK: a complete vault list across chosen networks, a 90-day daily APY series for one vault, and a one-vault report against the network's USD benchmark. Use it for dashboards, research notes and allocator reports. REST versions are in the recipes [paginate all vaults](/recipes/paginate-all-vaults) and [vault history vs benchmark](/recipes/vault-history-vs-benchmark).

Tested on 2026-10-23 with **`@vaultsfyi/sdk` 2.3.14** and **`vaultsfyi` 1.3.0** against the live API. The SDKs send the key as `x-api-key`. APY values are decimal fractions (`0.0315` = 3.15 %); timestamps are Unix seconds.

## Prerequisites

- An API key in `VAULTSFYI_API_KEY` ([SDK quickstart](/sdk/quickstart)).
- TypeScript: Node.js 18+, `@vaultsfyi/sdk@2.3.14`, ESM. Python: Python 3.8+, `vaultsfyi==1.3.0`.

## TypeScript

```typescript
// Data analytics with @vaultsfyi/sdk 2.3.14: page through a vault list, pull 90 days of daily APY,
// compare with the USD benchmark, and print a one-vault report. Node >= 18, ESM.
import { VaultsSdk } from '@vaultsfyi/sdk';

const sdk = new VaultsSdk({ apiKey: process.env.VAULTSFYI_API_KEY! }); // sent as x-api-key
const NETWORK = 'base';
const VAULT_ID = '0xbeeff2490FEffa212faC2f6553682C219E6a8845'; // Steakhouse High Yield USDC
const pct = (x: number) => `${(x * 100).toFixed(2)} %`; // APY fields are decimal fractions

// 1) Every USDT0 vault on Plasma and Ethereum, page by page. getAllVaults wraps GET /v2/detailed-vaults
//    and returns { itemsOnPage, nextPage?, data }, NOT an array. nextPage is absent on the last page.
//    Override the defaults: 4 networks (base, mainnet, arbitrum, optimism) and minTvl 100000.
const vaults = [];
let page = 0;
let calls = 0;
while (true) {
  const res = await sdk.getAllVaults({
    query: { allowedNetworks: ['plasma', 'mainnet'], allowedAssets: ['USDT0'], minTvl: 0, perPage: 10, page },
  });
  calls += 1;
  vaults.push(...res.data);
  if (res.nextPage === undefined) break;
  page = res.nextPage;
}
console.log(`${vaults.length} vaults in ${calls} pages, ~${calls + 3 * vaults.length} credits (1 per call + 3 per vault)`);

// 2) 90 days of daily 7-day APY. granularity defaults to 1hour and perPage to 50: set both.
const toTimestamp = Math.floor(Date.now() / 1000 / 86400) * 86400; // Unix SECONDS, midnight UTC
const fromTimestamp = toTimestamp - 90 * 86400;
const history = await sdk.getVaultHistoricalApy({
  path: { network: NETWORK, vaultId: VAULT_ID },
  query: { granularity: '1day', apyInterval: '7day', fromTimestamp, toTimestamp, perPage: 100 },
}); // oldest first; ~91 credits (1 + 1 per point)
const series = history.data.map((p) => p.apy.total);
const mean = series.reduce((a, b) => a + b, 0) / series.length;
console.log(`${series.length} daily points, mean 7d APY ${pct(mean)}, min ${pct(Math.min(...series))}, max ${pct(Math.max(...series))}`);

// 3) Report: current vault data and the network's USD benchmark, same 7-day window.
const [vault, bench, benchHist] = await Promise.all([
  sdk.getVault({ path: { network: NETWORK, vaultId: VAULT_ID } }),                  // 3 credits
  sdk.getBenchmarks({ path: { network: NETWORK }, query: { code: 'usd' } }),         // 3 credits; code required
  sdk.getHistoricalBenchmarks({                                                      // 3 + 3 per point
    path: { network: NETWORK },
    query: { code: 'usd', fromTimestamp: toTimestamp - 3 * 86400, toTimestamp, perPage: 10 },
  }),
]);
if (!bench.apy) throw new Error('no benchmark for this network'); // typed nullable
const report = {
  name: vault.name,
  apy7d: pct(vault.apy['7day'].total),
  tvlUsd: Number(vault.tvl.usd),
  vaultScore: Math.round((vault.score?.vaultScore ?? 0) * 10) / 10,
  benchmark7d: pct(bench.apy['7day'].total),
  spreadBp: Math.round((vault.apy['7day'].total - bench.apy['7day'].total) * 10_000),
  benchmarkHistoryPoints: benchHist.itemsOnPage, // historical benchmarks are short; check before charting
};
console.log(JSON.stringify(report));
```

```python
import time

from vaultsfyi import VaultsSdk

NETWORK = "base"
VAULT_ID = "0xbeeff2490FEffa212faC2f6553682C219E6a8845"  # Steakhouse High Yield USDC (passed as vault_address)


def pct(x):
    return f"{x * 100:.2f} %"  # APY fields are decimal fractions


# 1) Every USDT0 vault on Plasma and Ethereum. Returns a dict {itemsOnPage, nextPage?, data}; nextPage is
#    absent on the last page. Override the 4-network default and minTvl=100000.

while True:

    if "nextPage" not in res:

to_ts = int(time.time()) // 86400 * 86400  # Unix SECONDS, midnight UTC

                                          from_timestamp=to_ts - 90 * 86400, to_timestamp=to_ts, per_page=100)
series = [p["apy"]["total"] for p in history["data"]]  # oldest first
print(f"{len(series)} daily points, mean 7d APY {pct(statistics.mean(series))}, "
      f"min {pct(min(series))}, max {pct(max(series))}")

# 3) Report: vault vs the network's USD benchmark, same 7-day window.
vault = client.get_vault(NETWORK, VAULT_ID)
bench = client.get_benchmarks(NETWORK, "usd")  # code is required: "usd" or "eth"
v7, b7 = vault["apy"]["7day"]["total"], bench["apy"]["7day"]["total"]
print({"name": vault["name"], "apy7d": pct(v7), "tvlUsd": int(vault["tvl"]["usd"]),
       "vaultScore": round(vault["score"]["vaultScore"], 1), "benchmark7d": pct(b7),
       "spreadBp": round((v7 - b7) * 10_000)})
```

## Step notes

### Vault lists are envelopes

`getAllVaults` returns `{ itemsOnPage, nextPage?, data, errors }`. Loop on `nextPage` and stop when it is absent (never `null`). There is no total count. Defaults hide data: only base, mainnet, arbitrum and optimism, only TVL ≥ $100,000, ascending sort. For a full-market dataset, pass every network as repeated `allowedNetworks` values and `minTvl: 0`.

### History parameters

`granularity` (spacing: `1hour`, `1day`, `1week`; default `1hour`) and `apyInterval` (smoothing window: `1day`, `7day`, `30day`, `90day`; default `7day`) are different things. With the defaults and `perPage` 50 you get about two days of hourly points. 90 days at `1day` is 90 points, one call with `perPage: 100`.

### Benchmarks

`code` is required (`usd` or `eth`). The benchmark is the TVL-weighted APY of the five largest vaults of that denomination on the network ([benchmark rates](/methodology/benchmark-rates)). Compare windows like for like (`apy['7day'].total` on both sides).

### Parallel requests

`Promise.all` over three requests is fine. For large backfills, run sequentially or with a small concurrency limit and back off on errors: the TypeScript SDK does not retry, the Python SDK retries 429/5xx three times.

## Pitfalls fixed from earlier versions of this tutorial

- The pagination loop treated `getAllVaults()` as an array (`push(...result)`, `result.length`) → use `res.data` and stop when `res.nextPage` is absent.
- `path: { network, vaultAddress }` → `path: { network, vaultId }` in every TypeScript call.
- `import { HttpResponseError }` → not exported; catch `Error` and read `message` ([SDK errors](/sdk/reference#errors-and-retries)).
- 90-day history at the default hourly granularity returned only the oldest points → `granularity: '1day'`.
- `currentApy: vault.apy` (an object of windows) → `vault.apy['7day'].total` (decimal).
- TypeScript-only → every step also in Python.
