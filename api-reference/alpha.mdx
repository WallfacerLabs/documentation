This page indexes every `/alpha` endpoint (11 operations) and links each one to its reference page. Alpha covers cross-chain intents, the CCTP USDC bridge, daily vault flows, a wallet's historical positions and balances, and vault holders. Use it to find the right alpha endpoint and its required inputs.

Alpha endpoints are early access. They may change or be removed **without notice** and carry no stability guarantee, so don't depend on them in production flows that need stability. What each stability level promises is on [Versioning and stability](/api-reference/versioning).

Requests go to `https://api.vaults.fyi` (no version suffix; the `/alpha` prefix is part of each path) with the header `x-api-key: $VAULTSFYI_API_KEY`. Every API key can call /alpha endpoints. /alpha endpoints need an API key (they are currently not offered over [x402](/ai-agents/x402)); an invalid key returns 401.

Unless a row says otherwise: APY values are decimal fractions (`0.0315` = 3.15%), token amounts are integer strings in base units, timestamps are Unix seconds, and list filters that take several values use repeated keys (`allowedNetworks=base&allowedNetworks=arbitrum`). See [Conventions](/api-reference/conventions).

Alpha endpoints cost 0 credits during early access, but they still need an API key.

Alpha endpoints are free during early access; pricing may be introduced later and would be announced in the changelog.

## Cross-chain intents

Quote, execute and track intent-based moves into a vault on another chain. Only **deposits into vaults** are supported: a token-to-token quote returns 400.

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`POST /alpha/transactions/intent/getQuote`](/api-reference/cross-chain/create-transaction-intent-quote) | Quote a cross-chain move into a vault (only deposits into vaults are supported). Returns a Permit2 payload to sign. | Body: `userAddress`, `inputPosition`, `outputPosition`, `feeToken`, `provider` | 0 (free during early access) |
| [`POST /alpha/transactions/intent/execute`](/api-reference/cross-chain/execute-transaction-intent) | Submit a signed intent quote (`payloadSignature`, `provider`). | Body: `payloadSignature`, `provider` | 0 (free during early access) |
| [`GET /alpha/transactions/intent/status`](/api-reference/cross-chain/get-transaction-intent-status) | Track an intent. | Query: `crosschainTransactionId`, `provider` | 0 (free during early access) |

Things to know:

- The quote returns a Permit2 payload. The user signs it; you send the signature to the execute endpoint as `payloadSignature`. Never sign on the user's behalf. See [Transaction safety](/ai-agents/transaction-safety).

## CCTP bridge

Bridge USDC between networks with Circle CCTP: context, unsigned bridge and claim transactions, in-transit transfers and status.

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`GET /alpha/transactions/cctp/context/{userAddress}/{srcNetwork}/{dstNetwork}/{assetAddress}`](/api-reference/cctp-bridge/get-cctp-transaction-context) | Balances, fees and options before a USDC bridge. Not every enum network is supported (gnosis returns 400). | Path: `userAddress`, `srcNetwork`, `dstNetwork`, `assetAddress` | 0 (free during early access) |
| [`GET /alpha/transactions/cctp/transactions/{action}/{userAddress}/{srcNetwork}/{dstNetwork}`](/api-reference/cctp-bridge/create-cctp-transaction) | Build unsigned CCTP bridge or claim transactions. | Path: `action`, `userAddress`, `srcNetwork`, `dstNetwork` | 0 (free during early access) |
| [`GET /alpha/transactions/cctp/money-in-transit/{userAddress}`](/api-reference/cctp-bridge/list-cctp-money-in-transit) | List a wallet's CCTP transfers that have not arrived yet. | Path: `userAddress` | 0 (free during early access) |
| [`GET /alpha/transactions/cctp/status`](/api-reference/cctp-bridge/get-cctp-transaction-status) | Status of a CCTP burn. Set a polling timeout. | Query: `burnTxHash`, `srcNetwork` | 0 (free during early access) |

Things to know:

- Not every network in the `network` enum supports CCTP: `gnosis` as destination returned 400 "not supported for CCTP".
- **Poll `getCctpTransactionStatus` with a timeout** and confirm the burn transaction onchain.

## Historical flows

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`GET /alpha/historical/{network}/{vaultId}/daily-flows`](/api-reference/historical/get-historical-daily-vault-flows) | Daily inflows and outflows for one vault. `fromDate` / `toDate` are `YYYY-MM-DD` strings; flows are base-unit strings. | Path: `network`, `vaultId`; Query: `fromDate`, `toDate` | 0 (free during early access) |

`fromDate` and `toDate` are `YYYY-MM-DD` strings, not Unix timestamps. `totalDeposits` and `totalRedemptions` are integer strings in the vault asset's base units (USDC: divide by 10^6).

## Historical positions

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`GET /alpha/historical-positions/{userAddress}`](/api-reference/historical-positions/list-user-historical-positions) | A wallet's past vault positions (latency around 40 s). | Path: `userAddress` | 0 (free during early access) |

This endpoint took about 40 s on a busy wallet. Use a client timeout of at least 60 s.

## Historical balances

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`GET /alpha/historical-balances/{userAddress}/{timestamp}`](/api-reference/historical-positions/list-user-historical-balances) | A wallet's vault balances at one Unix-seconds `timestamp`. Default 4-network scope. | Path: `userAddress`, `timestamp` | 0 (free during early access) |

This endpoint (about 13 s on a busy wallet) takes a Unix-**seconds** `timestamp` in the path and has the same default 4-network scope as v2 positions (base, mainnet, arbitrum, optimism). Pass `allowedNetworks` (repeated key) for others.

## Holders

| Endpoint | Use it when | Required inputs | Credits |
| - | - | - | - |
| [`GET /alpha/{network}/{vaultId}/holders`](/api-reference/holders/list-vault-holders) | Holders of one vault and their LP-token balances (`perPage` ≤ 1000, default 100). | Path: `network`, `vaultId` | 0 (free during early access) |

`balance` is the holder's LP-token (share) balance in LP-token base units (usually 18 decimals), not underlying-asset units. To convert to assets, multiply by the vault's share price (for example from [NRT share price](/api-reference/nrt/get-vault-nrt-share-price)).

Credits come from [Credits](/plans/credits): base cost per call, plus a per-item cost where shown. Pay-as-you-go is $0.002 per credit.

## Example: top holders of a vault

```bash
curl -H "x-api-key: $VAULTSFYI_API_KEY" \
  "https://api.vaults.fyi/alpha/base/0xbeeff2490FEffa212faC2f6553682C219E6a8845/holders?perPage=2"
```

Response, captured 2026-10-23 (complete):

```json
{
  "itemsOnPage": 2,
  "nextPage": 1,
  "data": [
    { "address": "0x2F865596972C0B3567bA636325C71ebaA8Cc1238", "balance": "4952501653832690363227033" },
    { "address": "0x295e9F0B609181200bF5eeBBDb9103aDfA27D56D", "balance": "4933566597919131996363419" }
  ]
}
```

`4952501653832690363227033` / 10^18 ≈ 4,952,501.65 vault shares. The path order is `/alpha/{network}/{vaultId}/holders`: network first, with no section name before it.

## Example: daily flows

```bash
curl -H "x-api-key: $VAULTSFYI_API_KEY" \
  "https://api.vaults.fyi/alpha/historical/base/0xbeeff2490FEffa212faC2f6553682C219E6a8845/daily-flows?fromDate=2026-10-01&toDate=2026-10-05&perPage=3"
```

Response, captured 2026-10-23 (trimmed to 1 of 3 days):

```json
{
  "itemsOnPage": 3,
  "nextPage": 1,
  "data": [
    {
      "date": "2026-10-01",

      "depositCount": 7806,
      "redemptionCount": 987,
      "uniqueDepositors": 2616,
      "uniqueRedeemers": 746
    }
  ]
}
```
