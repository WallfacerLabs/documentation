This page is the starting point for the vaults.fyi REST API. It gives you the base URL, how to authenticate, a first request with its real response, and the conventions every endpoint shares: units, pagination, hidden defaults and errors. It ends with a map of every endpoint section. Read it before you write client code or let an agent call the API.

The API serves DeFi vault data (APY, TVL, Reputation Score, fees, holders) and wallet portfolios, and it builds **unsigned**, ready-to-sign transaction payloads. The stable `/v2` surface covers 22 EVM networks. Solana (SVM), borrow markets, fixed-term (Pendle) and advanced analytics are in `/beta`. Cross-chain intents, CCTP bridging, vault holders and historical positions are in `/alpha`.

## Base URL and version prefixes

The base URL is `https://api.vaults.fyi` with **no** version suffix. Every path carries its own version prefix:

| Prefix | Stability | Example |
| - | - | - |
| `/v2/...` | Stable; breaking changes get at least 30 days' notice (35 operations) | `https://api.vaults.fyi/v2/detailed-vaults` |
| `/beta/...` | Stable in practice, shape may change without notice (32 operations) | `https://api.vaults.fyi/beta/svm/vaults` |
| `/alpha/...` | Early access, may change without notice (11 operations) | `https://api.vaults.fyi/alpha/base/{vaultId}/holders` |

The OpenAPI specs declare `servers: [{url: "https://api.vaults.fyi"}]`, and every spec path already starts with `/v2`, `/beta` or `/alpha`. If you configure `https://api.vaults.fyi/v2` as the base URL in a generated client, every request goes to `/v2/v2/...` and returns 404, and `/beta` and `/alpha` are unreachable. Set the base URL to `https://api.vaults.fyi`.

What each stability level promises is covered in [Versioning and stability](/api-reference/versioning).

## Authentication

Send your API key in the `x-api-key` header on every REST request:

```bash
curl -H "x-api-key: $VAULTSFYI_API_KEY" "https://api.vaults.fyi/v2/networks"
```

- Get a key at [portal.vaults.fyi/signup](https://portal.vaults.fyi/signup). Every key can call every endpoint (v2, beta and alpha). Plans differ only in price, included credits, rate limit and support. See [Plans and pricing](/plans/overview).
- **No key, v2 endpoints:** HTTP **402** with an x402 v2 payment challenge, not 401. You can pay per request with USDC on Base instead of using a key. See [x402](/ai-agents/x402).
- **No key, beta, alpha and NRT endpoints:** these need an API key; they are not offered over x402.
- **Invalid key:** HTTP **401** with the message "An API key is required…". Branch on the status code, not the message.
- **Public:** `GET /v2/health` needs no key.
- **MCP is different.** The hosted MCP server takes the same key as `Authorization: Bearer <key>`, not `x-api-key`. See [MCP server](/ai-agents/mcp-server).

Never hard-code the key. Read it from an environment variable (`VAULTSFYI_API_KEY` in the examples).

## Your first request

This request lists the two highest 7-day-APY USDC vaults on Base with at least $1M TVL:

```bash
curl -H "x-api-key: $VAULTSFYI_API_KEY" \
  "https://api.vaults.fyi/v2/detailed-vaults?allowedNetworks=base&allowedAssets=USDC&minTvl=1000000&sortBy=apy7day&sortOrder=desc&perPage=2"
```

```python
import os, requests

resp = requests.get(
    "https://api.vaults.fyi/v2/detailed-vaults",
    headers={"x-api-key": os.environ["VAULTSFYI_API_KEY"]},
    params={
        "allowedNetworks": "base",
        "allowedAssets": "USDC",
        "minTvl": 1000000,
        "sortBy": "apy7day",
        "sortOrder": "desc",
        "perPage": 2,
    },
    timeout=30,
)
resp.raise_for_status()
body = resp.json()
for v in body["data"]:
    print(v["name"], f'{v["apy"]["7day"]["total"] * 100:.2f}%', v["tvl"]["usd"])
```

```typescript
const params = new URLSearchParams({
  allowedNetworks: "base",
  allowedAssets: "USDC",
  minTvl: "1000000",
  sortBy: "apy7day",
  sortOrder: "desc",
  perPage: "2",
});
const res = await fetch(`https://api.vaults.fyi/v2/detailed-vaults?${params}`, {
  headers: { "x-api-key": process.env.VAULTSFYI_API_KEY! },
});
if (!res.ok) throw new Error(`${res.status} ${await res.text()}`);
const body = await res.json();
for (const v of body.data) {
  console.log(v.name, `${(v.apy["7day"].total * 100).toFixed(2)}%`, v.tvl.usd);
}
```

Response, captured 2026-10-23 and trimmed to the first vault and its key fields (the real item also has `protocol`, `score`, `holdersData`, `rewards`, `lpToken`, `flags`, `isCorrupted` and more):

What this response shows:

- `apy.7day.total` is `0.3136`, a **decimal fraction**: 31.36%, not 0.31%.
- `tvl.usd` is a string of whole USD. `tvl.native` is in the asset's **base units**: 5709308677428 / 10^6 = 5,709,308.68 USDC.
- The top-ranked vault carries a `warnings` entry. Ranking by APY surfaces risky vaults first. Check `warnings`, `flags` and `score.vaultScore` before you recommend a vault.
- `nextPage: 1` means another page exists. On the last page the key is **absent**.
- `errors` lists filter values the server did not recognise. Here it is empty.

## Conventions you must know

The full rules are on [Conventions](/api-reference/conventions). These are the ones that most often cause silent bugs:

| Topic | Rule |
| - | - |
| APY | Decimal fraction, net of fees: `0.0315` = 3.15%. Shape `apy.<window>.{base, reward, total}`, where `total = base + reward`. Windows on detailed vaults: `1hour`, `1day`, `7day`, `30day`, `90day`. Values can be negative or far above 1. |
| Token amounts | Integer strings in base units. 1 USDC = `"1000000"` (6 decimals). Transaction `amount` must be base units; `amount=1.5` returns 400. |
| USD values | Strings (`tvl.usd`, `balanceUsd`, `assetPriceInUsd`). Parse them as decimals. |
| Timestamps | Unix **seconds** (`fromTimestamp=1792540800`). Milliseconds return 400. |
| Networks | Name (`base`, `mainnet`) or CAIP-2 (`eip155:8453`). A bare chain ID (`8453`) or `ethereum` is rejected. |
| Array query params | Repeat the key: `allowedNetworks=base&allowedNetworks=arbitrum`. A comma list (`base,arbitrum`) returns 200 with **0 results**. |
| Default network scope | `/v2/detailed-vaults` and the `/v2/portfolio/*` endpoints cover only **base, mainnet, arbitrum, optimism** unless you pass `allowedNetworks`. `/v2/vaults` and `/v2/assets` cover all networks. |
| Other defaults | `minTvl=100000` (USD) hides small vaults; `sortOrder=asc` puts the lowest first, so send `sortOrder=desc` to rank. |
| Soft errors | Unknown filter values return **200** with empty `data` and the value echoed in `errors.unsupportedNetworks` / `unsupportedAssets` / `unsupportedProtocols`. |
| Positions | In `/v2/portfolio/positions`, `asset.balanceNative` / `asset.balanceUsd` are the wallet's **idle balance** of the underlying, repeated on every position. Position size is `asset.positionValueInAsset` or `lpToken.balanceUsd`. |

## Pagination

List endpoints take `page` (0-based, default 0) and `perPage` (default 50). The maximum `perPage` depends on the endpoint: 5000 for vault and asset lists, 20000 for historical series, 1000 for some beta lists. `perPage=0` returns 400.

Paginated responses look like `{ "itemsOnPage": n, "nextPage": n+1, "data": [...], "errors": {...} }`:

- `nextPage` is **omitted** on the last page. It is never `null`, so loop while the key is present.
- There is no total count. The only way to know how many items exist is to page to the end.
- A `page` past the end returns 200 with `itemsOnPage: 0` and `data: []`.
- `/v2/portfolio/*` endpoints are not paginated: they return everything in `{ "data": [...], "errors": {...} }`.

Copy-paste loops in Python and TypeScript are on [Conventions → Pagination](/api-reference/conventions#pagination).

## Errors and rate limits

Branch on the HTTP status first. The full catalog, with real bodies, is on [Errors and rate limits](/api-reference/errors).

| Status | Meaning (observed 2026-10-23) | Retry? |
| - | - | - |
| 400 | Validation failure (`message` is a JSON-encoded array of Zod issues), or a v2 resource not found (`"Vault … on network base not found"`) | No, fix the request |
| 401 | Invalid key | No |
| 402 | No `x-api-key` on a v2 endpoint: x402 payment challenge | No, add the key |
| 403 | Credits exhausted (documented in the spec; not observed) | No, top up |
| 404 | Unknown route, wrong HTTP method, or a beta resource not found | No |
| 429 | Rate limit exceeded (documented; not observed) | Yes, after `x-ratelimit-reset` seconds |
| 500 | Server error | At most once, then report |
| 503, 504 | Upstream or gateway timeout; 504 carries `retry-after: 120` | Yes, with backoff |

Authenticated responses carry `x-ratelimit-limit`, `x-ratelimit-remaining` and `x-ratelimit-reset` (seconds until the window resets). The key used to write these docs reported `x-ratelimit-limit: 600` over a 60-second window. Plan limits are on [Plans and pricing](/plans/overview).

## Credits

Each request consumes credits: a base cost per call plus, on some list endpoints, a cost per returned item. For example, `/v2/detailed-vaults` costs 1 + 3 per vault returned, so `perPage=50` costs up to 151 credits. Pay-as-you-go is $0.002 per credit. The full table is on [Credits](/plans/credits).

## OpenAPI specs

Use the specs for code generation and agent tool definitions. Remember to set the client base URL to `https://api.vaults.fyi`.

- v2 (stable): [https://api.vaults.fyi/v2/documentation/json](https://api.vaults.fyi/v2/documentation/json)
- beta: [https://api.vaults.fyi/beta/documentation/json](https://api.vaults.fyi/beta/documentation/json)
- alpha: [https://api.vaults.fyi/alpha/documentation/json](https://api.vaults.fyi/alpha/documentation/json)

The v2 spec's `info.description` says "Basic API key use is limited to 10 requests per minute". That figure is the limit for requests without an API key (per IP), not a plan limit. Keys get 600 to 3,000 requests per minute depending on the plan: see [Plans and pricing](/plans/overview) and the `x-ratelimit-*` headers.

## Transactions are unsigned

Transaction endpoints return calldata only. They do not sign, broadcast, simulate or check balances. The `simulate` parameter is deprecated and ignored. Before you ask a user to sign, verify `tx.chainId`, `tx.to`, the asset and the amount in base units, and run the `actions[]` in order. See [Transactions](/api-reference/transactions) and [Transaction safety for agents](/ai-agents/transaction-safety).
